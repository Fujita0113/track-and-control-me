# server-port-fallback Specification

## Purpose
サーバー起動時のポート自動フォールバック、フォールバック発生時の開発用DBへの自動切替と初回サンプルデータ投入、起動ポート・接続先DBの可視化を管理する。

## Requirements

### Requirement: 起動ポートの自動フォールバック

サーバーは SHALL、起動時に設定ポート(環境変数 `PORT` > `config.local.json` の `port` >
既定値)へのバインドを試みなければならない。既に使用中の場合はクラッシュしてはならない
(MUST NOT)。そのポート番号+1から順に空きポートを最大20個まで探索してバインドする。
全て使用中だった場合のみ、エラーを明示してプロセスを終了する。

#### Scenario: いつものポートが空いている
- **WHEN** 設定ポートが誰にも使われていない状態で `npm run server` を実行する
- **THEN** サーバーは設定ポートでリッスンを開始する

#### Scenario: いつものポートが使用中
- **WHEN** 設定ポートに別プロセス(例: 本チェックアウト側で起動中の同サーバー)が既に
  バインドしている状態で、別のディレクトリ(例: git worktree)から `npm run server` を
  実行する
- **THEN** サーバーはクラッシュせず、設定ポート+1以降で最初に見つかった空きポートで
  リッスンを開始する

#### Scenario: 空きポートが1つも見つからない
- **WHEN** 設定ポートから探索範囲内(最大20個)の全ポートが使用中である
- **THEN** サーバーは「空きポートが見つからない」ことが分かるエラーメッセージを出力して
  終了する

### Requirement: フォールバック時の開発用DBへの自動切替

サーバーは MUST、DB 接続先を明示指定(`DB_PATH` 環境変数、または `config.local.json` の
`dbPath`)していない場合、実際にバインドできたポートが設定ポートと一致すれば通常の実DBに、
一致しなければ(フォールバックが発生していれば)実DBとは別ファイルの開発用DBに接続しなければ
ならない。明示指定がある場合は、フォールバックの有無によらず常にその指定を優先する。

#### Scenario: いつものポートで起動 → 実DBに接続
- **WHEN** DB接続先を明示指定せずに起動し、設定ポートでバインドに成功した
- **THEN** サーバーは `<serverRoot>/data/track.sqlite` に接続する

#### Scenario: フォールバックポートで起動 → 開発用DBに接続
- **WHEN** DB接続先を明示指定せずに起動し、設定ポートが使用中でフォールバックポートで
  バインドした
- **THEN** サーバーは実DBとは別ファイルの開発用DB(`<serverRoot>/data/track.dev.sqlite`)に
  接続し、実DBには一切書き込まない

#### Scenario: 明示指定は常に優先される
- **WHEN** `DB_PATH` 環境変数(または `config.local.json` の `dbPath`)が指定された状態で
  起動し、フォールバックポートでバインドした
- **THEN** サーバーはフォールバックの有無に関わらず、明示指定されたDBに接続する

### Requirement: 開発用DBの初回サンプルデータ投入

サーバーは SHALL、開発用DBファイルが存在しない状態から新規作成された場合に限り、起動時に
カンバンタスクと長期目標のサンプルデータを最小限投入しなければならない。既に存在する
開発用DBファイルに対しては再投入してはならない(MUST NOT)。投入済みのデータはリセットせず、
そのまま使い続けられる(繰り返しの動作確認に同じテストデータを使い回すため)。

#### Scenario: 開発用DBを新規作成した
- **WHEN** 開発用DBのファイルパスにまだファイルが存在しない状態でサーバーがフォール
  バックポートで起動した
- **THEN** サーバーは起動処理の中でカンバンタスクと長期目標のサンプルデータを投入してから
  リッスンを開始する

#### Scenario: 既存の開発用DBを再利用する
- **WHEN** 開発用DBのファイルが既に存在する状態でサーバーがフォールバックポートで起動した
- **THEN** サーバーはサンプルデータの再投入を行わず、既存のデータをそのまま使用する

### Requirement: 起動ポートの可視化

サーバーは SHALL、起動完了時に実際にバインドしたホスト・ポート番号と、フォールバックが
発生したかどうか・どちらのDBに接続しているかを、標準出力から目視で判別できる形で
表示しなければならない。

#### Scenario: 起動完了時にポートとDBの種別が分かる
- **WHEN** サーバーの起動(リッスン開始)が完了する
- **THEN** 標準出力に、実際にバインドされたホスト・ポート番号、およびフォールバックが
  発生したかどうか・接続先DBの種別を含む行が表示される
