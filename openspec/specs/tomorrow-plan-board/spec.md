# tomorrow-plan-board Specification

## Purpose

「明日の計画」ビューに埋め込む登録用カンバン盤面の範囲を規定する。持ち込む機能（4列・列間ドラッグ・新規登録・期限調整・明日トグル既定 ON・見切れとめくり）と、持ち込まない機能（完了演出・設定ポップオーバー・カテゴリ付けモード）の境界、および右サイドバーへ供給する `詳細` / `アクティビティログ` の内容を定める。

## Requirements

### Requirement: 明日の計画ビューへの登録用カンバン盤面の埋め込み

「明日の計画」ビューは、本物のカンバン盤面（`保留` / `未着手` / `進行中` / `完了` の4列）を埋め込んで表示しなければならない（MUST）。盤面のカード・列の意匠は既存カンバン（`kb-*`）をそのまま用いなければならない（MUST。振り返り専用の別意匠へ描き直してはならない＝MUST NOT）。

- 盤面に現れるカードは、カンバンタブと同じく**葉だけ**でなければならない（MUST。`task-tree`「葉だけがカンバンのカードになる」に従う）。容れ物（子を持つタスク）を埋め込み盤面に表示してはならない（MUST NOT）。埋め込み盤面とカンバンタブで、出るカードの集合が食い違ってはならない（MUST NOT）。
- 盤面上でカードを列間へドラッグして移動できなければならない（MUST）。少なくとも `保留 → 未着手` と `未着手 → 進行中` の移動が行えなければならない（MUST）。これにより、今日やり残したタスクや保留に積んだタスクを明日へ引き取れる。
- 列内での新規タスク登録ができなければならない（MUST）。ここで作られるタスクは根（親を持たない）でよい（MAY）。
- 盤面が左メインの表示幅に収まらない場合、盤面は**見切れてよい**（MAY）。見切れた列は盤面領域の横スクロールでめくれなければならない（MUST）。
- ドラッグ中に盤面領域の端へポインタを寄せたときの自動横スクロール（`kanban-drag-autoscroll`）は、埋め込み盤面でも機能しなければならない（MUST。画面外の「完了」列へドロップできる）。

#### Scenario: 保留から未着手へ引き取る
- **WHEN** ユーザーが「明日の計画」ビューを開き、保留列のカード「OpenWork 面接対策」を未着手列へドラッグする
- **THEN** そのタスクは未着手（TODO）へ移動し、盤面に反映される

#### Scenario: 未着手から進行中へ動かす
- **WHEN** ユーザーが未着手列のカードを進行中列へドラッグする
- **THEN** そのタスクは進行中（DOING）へ移動し、盤面に反映される

#### Scenario: 見切れた列をめくって見る
- **WHEN** 左メインの表示幅が盤面の全幅より狭く、右端の列が見切れている
- **THEN** 盤面領域を横スクロールすると見切れていた列が表示される

#### Scenario: 容れ物は埋め込み盤面にも出ない
- **WHEN** 子を持つタスクが存在する状態で「明日の計画」ビューを開く
- **THEN** 埋め込み盤面にはその容れ物のカードは現れず、配下の葉だけが現れる（カンバンタブと同じ集合）

### Requirement: 埋め込み盤面が持ち込まない機能の境界

埋め込み盤面は**登録と調整に必要な機能のみ**を提供しなければならない（MUST）。以下はカンバンタブ専用のままとし、埋め込み盤面へ持ち込んではならない（MUST NOT）。

- 完了列ドロップ時の演出（フロスト表示・粒子アニメーション）およびサウンド
- 設定ポップオーバー（サウンド切替等）
- カテゴリ付けモード

完了列へのドロップによる**アーカイブ動作そのもの**（カードがボードから消えログへ移ること）は、埋め込み盤面でも従来どおり機能しなければならない（MUST。演出のみを落とし、機能は落とさない）。

#### Scenario: 完了ドロップは演出なしでアーカイブされる
- **WHEN** ユーザーが埋め込み盤面でカードを完了列へドロップする
- **THEN** そのタスクはアーカイブされてボードから消え、アクティビティログへ現れる
- **AND** フロスト・粒子の演出およびサウンドは発生しない

#### Scenario: 設定ポップオーバーとカテゴリ付けモードは出ない
- **WHEN** ユーザーが「明日の計画」ビューの埋め込み盤面を見る
- **THEN** 設定ポップオーバーを開くコントロールおよびカテゴリ付けモードの切替は表示されない

### Requirement: 明日トグルの既定 ON と期日決定の整合

埋め込み盤面は「明日の計画モード（明日トグル）」の切替を提供しなければならない（MUST）。「明日の計画」ビューにおいて、このトグルは**既定で ON** でなければならない（MUST）。

- トグルの状態および期日決定は、既存の期日決定エンジン（`computeDue()`）と「明日の計画モード」の保持規則（その日限り・翌日は OFF へリセット）に整合しなければならない（MUST）。振り返り専用の別の期日規則を作ってはならない（MUST NOT）。
- トグルが ON のとき、埋め込み盤面での新規作成および `保留 → 未着手` / `保留 → 進行中` の移動では `due = 翌日` が付かなければならない（MUST）。

#### Scenario: 既定 ON で新規タスクが明日に入る
- **WHEN** 対象日が 7/26 で、ユーザーが「明日の計画」ビューを開き、未着手列で新規タスク「筋トレ」を登録する
- **THEN** そのタスクは `due = 7/27`（翌日）の未着手タスクとして作成される

#### Scenario: 保留からの引き取りにも明日の期日が付く
- **WHEN** 明日トグルが ON の状態で、保留列のカードを未着手列へドラッグする
- **THEN** そのタスクの期日は翌日へ更新される

#### Scenario: トグルを OFF にすると当日になる
- **WHEN** ユーザーが明日トグルを OFF にしたうえで新規タスクを登録する
- **THEN** そのタスクは `due = 作業日（当日）` として作成される

### Requirement: 右サイドバーへ供給する詳細とアクティビティログ

埋め込み盤面は、カードの**詳細**と**アクティビティログ**を右サイドバーのタブへ供給しなければならない（MUST）。左メインの内部に詳細パネル・ログを重ねて配置してはならない（MUST NOT）。

- 詳細タブは既存カンバンの詳細パネルの内容（優先度ピル・**カレンダー式の期限ピッカー**・ノートエディタ等）を提供しなければならない（MUST）。**期限の調整はこの詳細タブで行う**。
- カードを選択したとき、右サイドバーは自動的に**詳細タブへ切り替わら**なければならない（MUST）。
- タスクが完了（アーカイブ）されたとき、右サイドバーは**アクティビティログタブへ戻ら**なければならない（MUST）。
- ログタブは、アクティビティログの**上に本日達成したタスクの件数**（カンバンタブの「本日の進捗」と同じ表示）を供給しなければならない（MUST。issue #67 フィードバック: カンバンタブと同じ情報が埋め込み盤面でも見えること）。

#### Scenario: カードを選ぶと詳細が右に出る
- **WHEN** ユーザーが埋め込み盤面のカードをクリックする
- **THEN** 右サイドバーが詳細タブへ切り替わり、そのカードの詳細が表示される

#### Scenario: 詳細タブで期限を調整する
- **WHEN** ユーザーが右サイドバーの詳細タブでカレンダー式の期限ピッカーから別の日付を選ぶ
- **THEN** そのタスクの期日が更新され、盤面のカードの期限表示へ反映される

#### Scenario: 完了するとログへ戻る
- **WHEN** ユーザーがカードを完了列へドロップし、そのタスクがアーカイブされる
- **THEN** 右サイドバーはアクティビティログタブへ切り替わり、その完了がログに現れる

#### Scenario: ログタブに本日の達成件数が出る
- **WHEN** ユーザーが右サイドバーの「ログ」タブを開く
- **THEN** アクティビティログの上に、本日完了したタスクの件数（カンバンタブの「本日の進捗」相当）が表示される
