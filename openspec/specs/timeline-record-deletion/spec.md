# timeline-record-deletion Specification

## Purpose

タイムラインの自動記録（AUTO ラン／ブロック）をユーザーが削除できるようにする。削除は `session` 行の物理削除ではなく、identity と時間区間を持つ**除外レコード**として永続化し、`recompute()` による再集計をまたいで持続させる。除外区間は同時オープンだった他グループへ divide-by-N で再按分し、開いていたグループが全て除外された区間は `ungrouped` へ計上せず非計上（未記録ギャップ）として扱う。削除は確定済みの日にも適用でき、取り消しも可能とする。

## Requirements

### Requirement: 自動記録の削除は除外レコードとして永続化される

ユーザーはタイムラインの自動記録ラン／ブロックを削除 SHALL できる。削除は、対象の identity（`group-identity-registry` が解決する名前＋色の同一性）と時間区間 `[startAt, endAt)` を持つ**除外レコード**として永続化する SHALL。

`session` 行の物理削除に依存してはならない（MUST NOT）。`recompute()` は `raw_sample` からセッションを毎回作り直すため、除外レコードは再集計をまたいで持続 SHALL し、再集計後も削除された区間の当該 identity のセッションが再生成されてはならない（MUST NOT）。

削除は API `POST /api/timeline/:date/exclusions`（body: `identityKey`, `startAt`, `endAt`）で登録 SHALL し、登録後に対象日の再集計とルール評価を実行してから応答する SHALL。`identityKey` の欠落、`endAt <= startAt` は 400 を返す SHALL。

#### Scenario: 削除した自動記録は再集計しても復活しない

- **WHEN** 当日 13:00–15:00 の「開発」の自動記録ブロックを削除し、その後 `recompute()` を実行する
- **THEN** 13:00–15:00 に「開発」の `session` 行は存在せず、タイムラインにも「開発」のブロックは現れない

#### Scenario: 削除区間の外は影響を受けない

- **WHEN** 「開発」が 09:00–10:00 と 13:00–15:00 に記録されている日で、13:00–15:00 だけを削除する
- **THEN** 09:00–10:00 の「開発」のセッションと計上時間は削除前と変わらない

#### Scenario: 不正な区間の削除要求は拒否される

- **WHEN** `endAt` が `startAt` 以下の区間、または `identityKey` を欠いた body で削除 API を呼ぶ
- **THEN** 400 が返り、除外レコードは作成されず、集計は変化しない

### Requirement: 除外区間は「そのグループが開いていなかった」ものとして再按分される

除外レコードが覆う区間では、システムは当該 identity を**その区間に開いていなかったもの**として集計 SHALL する。区間に他の開いていたグループが残る場合、その区間の計上時間は残りのグループのみで divide-by-N（分母を N−1 へ）再按分 SHALL する。区間の計上時間の総和は削除の前後で変わらない SHALL。

残ったグループのセッションの同時オープングループ一覧（`coactiveGroupKeys`）から、削除された identity は除外 SHALL する。

#### Scenario: 2グループ同時オープンの一方を削除すると残りが全量になる

- **WHEN** 12:00–13:00 に「開発」と「ブログ投稿」が同時オープンで各30分が計上されている状態で、「開発」を削除する
- **THEN** 「ブログ投稿」の当該区間の計上は60分になり、その日の総作業時間は削除前と変わらない

#### Scenario: 3グループ中1つを削除すると残り2つが等分する

- **WHEN** 60分の区間に3グループが同時オープン（各20分）で、そのうち1つを削除する
- **THEN** 残り2グループの当該区間の計上はそれぞれ30分になる

#### Scenario: 削除されたグループは同時オープン一覧から消える

- **WHEN** 「開発」と同時オープンだった「ブログ投稿」のブロックの詳細を、「開発」の削除後に確認する
- **THEN** 同時に開いていたグループとして「開発」は表示されず、均等割の注記も当該区間には付かない

### Requirement: 開いていたグループが全て除外された区間は未計上になる

その区間に開いていた実グループがすべて除外された場合、システムはその区間を `ungrouped`（未グループ）へ計上してはならない（MUST NOT）。当該区間は**除外時間**（非計上）として扱い、`daily_totals_snapshot` のいずれのグループにも加算しない SHALL。その結果、その日の総作業時間は削除した区間の長さぶん減る SHALL。

未計上となった区間はタイムラインの未カバー区間となり、閾値 `away_min_seconds` 以上であれば `gaps` として返され、既存のゴーストスロットから手動記録し直せる SHALL。

#### Scenario: 単独オープンのブロックを削除すると総作業時間が減る

- **WHEN** 他グループが同時オープンでない 13:00–15:00（2時間）の「開発」ブロックを削除する
- **THEN** その日の総作業時間は削除前より2時間少なくなる

#### Scenario: 削除区間は未グループとして計上されない

- **WHEN** 単独オープンだった区間のブロックを削除する
- **THEN** その区間ぶんの時間が `ungrouped` の日次合計へ移ることはなく、どのグループの合計にも加算されない

#### Scenario: 削除区間は未記録ギャップとして記録し直せる

- **WHEN** 閾値以上の長さの単独オープンブロックを削除し、タイムラインを再表示する
- **THEN** その区間は未記録ギャップとして現れ、ゴーストスロットから手動記録できる

### Requirement: 削除は確定済みの日にも適用できる

削除は、日境界を越えて確定済み（`daily_totals_snapshot` / `unlock_evaluation` の `is_final = 1`）となった過去日に対しても実行 SHALL できる。この場合、システムは**削除対象日に限って**確定ガードを外して再集計し、当該日のルール評価も再実行 SHALL する。対象日以外の確定日を再計算・再評価してはならない（MUST NOT）。

削除は計上時間を減らす方向にのみ働くため、確定日の総作業時間が削除によって増えることはない SHALL。削除の結果その日が解錠条件を満たさなくなった場合、当該日の評価は未達成へ更新 SHALL され、目標の達成日数・完走レポートの集計へ反映される SHALL。

#### Scenario: 確定済みの過去日の記録を削除できる

- **WHEN** すでに `is_final = 1` となった2日前の「開発」ブロック（単独オープン・2時間）を削除する
- **THEN** その日の `daily_totals_snapshot` の「開発」の計上が2時間ぶん減り、削除は再集計後も保たれる

#### Scenario: 削除で条件を満たさなくなった確定日は未達成へ更新される

- **WHEN** 総作業3時間で「3時間以上」の条件を達成済みだった確定日から、1時間ぶんの記録を削除する
- **THEN** その日の評価は未達成へ更新され、目標の達成日数から1日減る

#### Scenario: 対象日以外の確定日は変化しない

- **WHEN** ある確定日の記録を削除する
- **THEN** 他の確定日の `daily_totals_snapshot` と `unlock_evaluation` は削除前と同一のまま変化しない

### Requirement: 削除は取り消せる

除外レコードは取り消し（削除の撤回）SHALL できる。取り消しは API `DELETE /api/timeline/exclusion/:id` で実行 SHALL し、対象日の再集計とルール評価を実行してから応答する SHALL。取り消し後の集計値は、その削除を行わなかった場合と一致 SHALL する。

存在しない除外レコード ID への取り消しは、エラーを発生させず「取り消すものが無かった」ことを示して応答 SHALL する（冪等）。

クライアントは削除の直後に取り消し導線を提示 SHALL する。

#### Scenario: 取り消すと削除前の集計へ戻る

- **WHEN** 「開発」の 13:00–15:00 を削除したのち、その除外レコードを取り消す
- **THEN** 「開発」のブロックとその日の総作業時間は削除前の値へ戻る

#### Scenario: 同時オープンの再按分も取り消しで戻る

- **WHEN** 「開発」の削除で60分になっていた「ブログ投稿」の区間について、削除を取り消す
- **THEN** 「ブログ投稿」の当該区間の計上は30分へ戻り、同時オープングループとして「開発」が再び現れる

#### Scenario: 取り消しは冪等

- **WHEN** すでに取り消した除外レコードの ID へもう一度取り消しを実行する
- **THEN** エラーにならず、集計は取り消し済みの状態から変化しない
