## Context

`goal-blueprint-task-tree` は実装済みで、テストは緑（vitest 514 / e2e `goal-blueprint-task-tree.spec.ts` 4本）。動くが、使ってみると**ツリーを作ったあと構造を触る手段が画面に無い**（issue #91 のフィードバック）。

現状の形:

- `blueprint.js:88-95` — `S.mode` で `previewEl()` と `importEl()` を出し分ける。
- `blueprint.js:126-166` `nodeEl()` — トグル、チェックボックス、タイトル、枝の操作。**追加・改名・削除は無い**。タイトルは `<span>`（`bp-node-title`）。
- `blueprint.js:176-208` `branchActionsEl()` — `この枝に着手する` と `この枝を打ち切る` を**すべての容れ物の行に常時2つ**出す。
- `importEl()` — 目標を指す `api.importGoalBlueprint(S.goalId, text)` を呼ぶだけ。取り込み先は常に根。
- サーバ側は既に揃っている: `createChildTask`（親の列を引き継ぐ・`DONE` は拒否）、`setParent`（循環検査）、`deleteTask`（子を繰り上げ）、`PATCH /api/tasks/:id`。**追加が要るのは `importBlueprint` の取り込み先だけ**。

issue #91 のうち、この change に入らないもの（別途、直接修正済み）:

- まとめて追加の入力欄を素の `<textarea>` から共有 Markdown エディタ（`createMarkdownEditor`）へ差し替え済み。Enter のマーカー継続と Tab の2スペース増減が効き、その2スペースが `parseBlueprintText` のインデント解釈と一致する。
- カンバンのパンくずをタイトルの上へ移し、丸ピルをやめて `親 ›` と読める素の文字にした（カテゴリバッジと形ごと分離）。

## Goals / Non-Goals

**Goals:**

- ツリーの上で子の追加・改名・削除ができる（カンバンへ回り込まなくてよい）
- まとめて追加の取り込み先を選べる（根固定をやめる）
- 画面名とボタン名が、何の画面か・何が起きるかを言っている

**Non-Goals:**

- ドラッグ&ドロップの並べ替え・再親付け UI（`setParent` は実装済みだが UI は別 issue）
- タスク一覧からのカテゴリ付与
- テキストとツリーの双方向同期（`goal-blueprint` の「追加のみの一方向」は維持）
- カンバン側のカード詳細の「このタスクを分解する」の撤去（同じ API を使う別の入口として残す）

## Decisions

### D1. モード切替を撤去し、ツリーを常に出す

`S.mode` と `modeToggleEl()` を消す。`renderAll()` は常に `previewEl()` を出し、まとめて追加は**ノード行から開く小さなパネル**にする。

- **なぜ**: 「取り込み」タブがツリーの姿を映さないことが混乱の直接の原因（issue #91-5）。2つの面のうち片方だけがデータを映していると、もう片方が壊れているように見える。面を1つにすれば、この不一致自体が消える。
- **代替案（モードは残し、取り込み側に現在のツリーをテキストで出す）を採らない理由**: それは双方向同期の入口で、行の書き換えが改名か削除＋新規か判別できない問題に戻る。

### D2. ノード行の編集導線は「＋」1つに寄せ、残りはホバーで出す

行が持つものが多すぎる（トグル・チェック・タイトル・着手・打ち切り・追加・削除）。常時出すのは**トグル・チェック・タイトル**だけにして、残りは**行ホバーで右側に出す**。

- `＋`（子を足す）… クリックでその行の直下にインライン入力を1つ開く。Enter で確定して**続けて次の入力を開く**（兄弟を連打で足せる）。Esc で閉じる。
- `⋯` … まとめて追加 / 枝への着手 / 枝の打ち切り / 削除 をメニューに畳む。
- **改名はダブルクリック**（カンバンのカードと同じ操作・`kanban.js:722` `cardTitleEl` の流儀をそのまま持ってくる）。行に改名ボタンを増やさない。

`task-tree` の spec が「枝の操作を各行に常時2つ並べてはならない」と言うのはここに対応する。

### D3. 「この枝に着手する」→ 件数入りの結果ラベル

`getBlueprint` の各ノードに、配下の `HOLD` の葉の件数（`holdLeafCount`）を足して返す。ラベルは `保留の3件を未着手へ`。`holdLeafCount === 0` なら導線ごと出さない。

- **なぜサーバで数えるか**: `getBlueprint` は既に全件からツリーを1度組んでいる（`task-tree.ts`）。同じ後順走査のついでに数えられる。クライアントで再帰を書くと導出が2箇所になる。
- 打ち切りのラベルも `⋯` の中では `この枝を打ち切る` のままでよい（メニュー項目なので文脈が読める）。

### D4. まとめて追加は `parentTaskId` を受ける

```
importBlueprint(db, goalId, text, parentTaskId = null)
POST /api/goals/:id/blueprint/import  { text, parentTaskId? }
```

`parentTaskId` があれば、パースした根を `createChildTask(db, parentTaskId, …)` でぶら下げる。`createChildTask` が既に「完了済みは拒否」を持っているので、spec の「完了済みへはまとめて追加できない」は**そこを通すだけで自動的に満たされる**。新しい検査を書かない。

- `parentTaskId` が指定されたとき、その親が別の目標のツリーに属していないことは検査する（他人の枝に紛れ込ませない）。

### D5. 追加後の再描画で開閉状態を失わせない

いまの `reload()` は `S.nodes` を差し替えて `renderAll()` するだけで `S.openSet` は保つ（`blueprint.js:57-66`）。ここは既に正しい。追加で要るのは**足した親を `openSet` に入れてから再描画する**ことだけ（`goal-blueprint` の「子を足した親は開いたままになる」）。

新しく作られたノードの id は `POST /api/tasks/:id/children` のレスポンスから取れるので、再取得を待たずに親 id を `openSet` へ足せる。

### D6. 名前の置き換え範囲

| 場所 | 変更 |
|---|---|
| `goals.js:264` 目標カードのボタン | `設計図` → `タスク一覧` |
| `goals.js:756` レポートからの導線 | `設計図を開く` → `タスク一覧を開く` |
| `blueprint.js:87` 見出し | `設計図 — <目標名>` → `タスク一覧 — <目標名>` |
| `blueprint.js:117-119` 空状態 | 「まだタスクがありません。「＋」から足せます。」 |
| `blueprint.js` 冒頭コメント | 設計図 → タスク一覧 |
| capability id `goal-blueprint` / ファイル名 `blueprint.js` / CSS 接頭辞 `bp-` | **変えない** |

識別子を変えないのは、画面に出ないうえに、変えると spec ディレクトリの移動と CSS 全面置換という中身と無関係な差分が出るため。

## Risks / Trade-offs

- [行ホバーで導線を出すと、タッチ環境や「どこを押せばいいか分からない」問題が起きる] → `＋` だけは**常時表示**にして、畳むのは `⋯` の中身だけにする。追加は一番よく使う操作なので隠さない。
- [インライン入力を Enter で連打できるようにすると、空文字で確定して空タスクが増える] → 空文字の Enter は**入力を閉じるだけ**にして何も作らない。
- [`goal-blueprint-task-tree` をアーカイブする前にこの change を apply すると、delta の当て先が無い] → 順序を tasks.md の §1 に固定する。
- [既存 e2e `goal-blueprint-task-tree.spec.ts` がモード切替（`取り込み` ボタン）を踏んでいる] → **propose のこの段階で直す**（apply では既存 e2e は凍結）。
- [ツリー上の削除が、着手済み・完了済みのカードを消す事故になる] → `deleteTask` は子を繰り上げるだけで子は消さない（実装済み）。加えて、**完了済みまたは子を持つノードの削除には確認を出す**。カンバンの `deleteTaskWithConfirm` と同じ流儀。

## Migration Plan

DB マイグレーション無し。`importBlueprint` の第4引数は省略可能なので、既存の呼び出し（`POST /api/goals/:id/blueprint/import` の `parentTaskId` 無し）はそのまま動く。

## Open Questions

- `⋯` メニューの中身の並び（まとめて追加 / 着手 / 打ち切り / 削除）と、葉のときに何を出すか（葉には着手・打ち切りが無いので、まとめて追加＝分解 と削除だけ）。実装しながら `ref/` のモックで見る。
- `＋` で開くインライン入力を、子として足すのか兄弟として足すのかを行のどこに置くかで区別するか。まずは**常に子として足す**（兄弟は親行の `＋` を押せばよい）で作る。
