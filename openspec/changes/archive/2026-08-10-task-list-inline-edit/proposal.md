## Why

`goal-blueprint-task-tree` を実際に使ってもらった結果、**ツリーを作ったあと構造を触る手段が画面に1つも無い**ことが分かった（issue #91 のフィードバック）。

子を作る導線はカンバンのカード詳細の「このタスクを分解する」1本だけで、容れ物は盤面に出ない。つまり:

- 対象が**葉**なら … カンバンへ行きカードを探して詳細を開けば分解できる（タスク一覧からは辿れない）
- 対象が**容れ物**なら … **手段が無い**

取り込み欄も常に空から始まり、`importBlueprint` は必ず**根に**足すため既存ノードの下へは入らない。「test2 の下にさらにタスクを生やす」ができない。

これは実装の抜けではなく提案の抜けである。元の設計相談では「テキスト取り込みは初回の骨組みだけ、以後の編集はアウトライナー UI」と決めていたのに、`goal-blueprint-task-tree` の提案がテキスト取り込みだけを持ち出し、構造編集の面を落とした。

同時に、名前が分かりにくいという指摘も来ている:

- 「**設計図**」が何の画面か伝わらない
- 「**プレビュー / 取り込み**」というモード名だと、取り込み側が常に空なのが不可解に見える（ツリーの姿が出ると期待される）
- 「**この枝に着手する**」がボタンとして何をするのか読めない

## What Changes

- **BREAKING（画面名）**: 利用者に見える名称を「設計図」から **「タスク一覧」** へ改める。capability の識別子（`goal-blueprint`）は画面に出ないため変更しない。
- **BREAKING（画面構成）**: **プレビュー / 取り込みのモード切替を廃止する**。ツリーは常に表示され、**それ自体が編集できる面**になる。
  - 各ノードに **「＋ 子を足す」**（1件をその場で追加）。葉に子を足せば分解になり、既存の `POST /api/tasks/:id/children` がそのまま使える。
  - ノードのタイトルは**その場で改名**できる（カンバンのカードと同じダブルクリック操作）。
  - ノードを**タスク一覧から削除**できる（既存の削除規則どおり、子は道連れにしない）。
  - 根（目標直下）にも同じ2つの追加導線を置き、新しい枝を足せる。
- **テキストの一括追加は「まとめて追加」として残し、取り込み先のノードを選べるようにする**（根固定をやめる）。追加のみの一方向という規則自体は変えない。
- 「この枝に着手する」を、**何が起きるかを言うラベル**へ改める（対象件数を含む。対象0件なら出さない）。枝の操作は**常時表示をやめる**（行ごとに2つのボタンが並び続けるのを避ける）。

## Capabilities

### New Capabilities

（なし。`goal-blueprint` / `task-tree` の要件変更のみ）

### Modified Capabilities

- `goal-blueprint`: 画面名の変更、モード切替の廃止とツリー自体の編集、まとめて追加の取り込み先指定
- `task-tree`: 枝への着手のラベル要件（何が起きるかを言い、対象0件では出さない）

## Impact

- **順序の制約**: この change は `goal-blueprint-task-tree` の delta を土台にしている。**先に `goal-blueprint-task-tree` をアーカイブして** `openspec/specs/goal-blueprint` / `openspec/specs/task-tree` を作ってからでないと、ここの MODIFIED / REMOVED は当てる先が無い。
- **フロント**: `server/static/js/blueprint.js`（モード切替の撤去、ノード行の追加・改名・削除、まとめて追加のノード指定）、`server/static/js/goals.js`（ボタン文言）、`server/static/css/app.css`
- **サーバ**: `importBlueprint(db, goalId, text)` に取り込み先の親を受け付ける引数を足し、`POST /api/goals/:id/blueprint/import` が `parentTaskId` を受け取る。ほかの API 追加は不要（追加＝`POST /api/tasks/:id/children`、改名・削除＝既存の `PATCH` / `DELETE /api/tasks/:id`）
- **既存 e2e**: `e2e/goal-blueprint-task-tree.spec.ts` がモード切替（`取り込み` ボタン）と `.bp-import-ed` を踏んでいるため、この change で直す
- **スコープ外**: ドラッグ&ドロップによる並べ替え・再親付けの UI（`setParent` の循環検査は実装済みだが UI は別 issue）、タスク一覧からのカテゴリ付与
