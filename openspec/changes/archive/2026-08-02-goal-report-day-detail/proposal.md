## Why

issue #76 のコメントで、理想の目標レポート像として次が挙がっていた：

> 棒グラフの何月何日のところを押すと、モーダルでその日のレポートが出てくる。何に何時間使って、目標時間を上回っていたのかどうなのか。ルールの達成状況は？5段階での気分評価は？その日振り返りではどんなことを記入した？そして振り返りはあとから編集することもできる。（中略）具体的なユースケースとしては、なにかショックな出来事があって振り返りできなかったときに、あとから埋めるシチュエーションを想像している。棒グラフ一つ一つにカーソルを合わせながら振り返りが書かれているかどうかを見て、書かれていないのがあったらクリックして記入するみたいな感じ。

この要求は `goal-target-hours-and-open-period`（issue #76 の別スレッド）の探索時に「①の棒グラフ化と日別モーダル」として一括りにし、次回送りにしていた。ユーザーとの確認で、**①達成カレンダーの見た目（ルール別マス目グリッド）は作り直さず、クリック／ホバーの機能だけを足す**方針が確定した。本変更はその実装分を切り出す。

現状、①のマスをクリックすると④「毎日の日記」までスクロールして**文面だけ**が読める（読み取り専用）。気分・時間の内訳・ルールの達成理由はそれぞれ別の場所（①のマス・振り返りタブ）に散らばっており、突き合わせるには画面を往復する必要がある。「書いたかどうか」を確認する手段も、1マスずつクリックして④を読みに行くしかない。

調査の結果、必要なデータは**すべて既存の経路で賄える**ことが分かった：
- レポート取得時に既に届いている `rep.days[dayNumber-1]`（目標日記→振り返りの日単位フォールバック済みテキスト）を、ホバー用プレビューにそのまま使える。
- レポート取得時に既に届いている `rep.rules[*].cells[dayNumber-1]`（met/実測/閾値/未到来/対象外/凍結）を、モーダルの「ルール達成状況」にそのまま使える。
- 時間の内訳は既存の `GET /api/summary?date=` で取れる。
- 気分・振り返り本文の取得・保存は既存の `GET/PUT /api/reflection/:date` で完結する（振り返りタブと同じデータ）。

**新しい DB・API・サービスは不要**で、フロントエンドの表示・操作だけの変更になる。詳細は `ユーザーフロー.md` を唯一の受け入れ基準とする。

## What Changes

- **ホバープレビュー**：①のマス（ルール行のセル、またはヘッダの Day 番号）にカーソルを合わせると、その日の文面プレビュー（`rep.days` の既存フォールバックテキスト、無ければ「未記入」）をツールチップで表示する。**新規のネットワーク取得を行わない**（レポート取得時に既に手元にあるデータのみを使う）。
- **日別詳細モーダル**：①のマスをクリックすると、既存の④選択・ハイライト更新（変更しない）に**加えて**、その日の詳細モーダルを開く。モーダルは3ブロック：
  - **この日にやったこと**：その日の各ルールの達成状況（met/未達/対象外/凍結・実測/閾値）。①のマスと同じ事実をルール名つきで並べる。
  - **時間の内訳**：`GET /api/summary?date=` を叩き、その日のタブグループ別実測時間を表示する。目標時間があれば、対象グループの実測をその日1日ぶんの目標時間と比べて表示する。
  - **気分・振り返り**：`GET /api/reflection/:date` で気分（5段階）と本文を取得し、**その場で編集して `PUT /api/reflection/:date` で保存**できる。保存後はレポート全体を再取得して再描画する（差分更新はしない）。
  - この目標に**目標の日記**（`goal_journal`）が別に存在する日は、読み取り専用で注記する（モーダルからの編集対象は「振り返り」のみ。目標日記の編集は既存どおり振り返りタブ／目標コーナーに残す）。
- **デモモードではモーダルを開かない**（ホバープレビューのみ動く）。デモは仮想日付・専用DBで動いており、`GET /api/summary` ／ `GET/PUT /api/reflection/:date` に対応する経路を持たないため。

**①達成カレンダーの見た目（ルール別マス目グリッド）・②〜⑤・沿革・目標時間・完走フォーク・目標日記の編集経路は一切変更しない。**

## Capabilities

### New Capabilities
- `goal-report-day-detail`: ①のホバープレビューとクリックで開く日別詳細モーダル。既存データ（`rep.days` / `rep.rules[*].cells`）と既存エンドポイント（`GET /api/summary`・`GET/PUT /api/reflection/:date`）の再利用のみで完結し、新規のDB・API・サービスを持たない。

### Modified Capabilities
- （なし）`goal-report` の既存要求（①のクリックで④が選択される・ルールごとのマス目グリッド等）は変更しない。本変更は追加のインタラクションを重ねるのみ。

## Impact

- **DB / API / サービス**: 変更なし。既存の `GET /api/summary`・`GET /api/reflection/:date`・`PUT /api/reflection/:date` をそのまま再利用する。
- **フロントエンド**: `server/static/js/goals.js`（①のセル/ヘッダへのホバー・クリックハンドラ拡張、日別詳細モーダルの新設）、`server/static/css/app.css`（ツールチップ・モーダルのスタイル）。
- **デモモード**: 変更なし（モーダルを出さない分岐を追加するのみ）。`demo-seed.ts` へのサンプル追加は不要。
- **vitest**: 追加なし（サービス・API層を一切変更しないため）。
- **e2e**: 既存 Playwright への影響なし（既存の①クリック挙動は変更しない）。新規に、ユーザーフローの背骨（ホバーでプレビュー → クリックでモーダル → 振り返りを編集して保存 → レポート再描画に反映）を1本追加する（apply 側で DOM 確定後に書く）。
