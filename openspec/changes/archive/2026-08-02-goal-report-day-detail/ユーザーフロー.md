# ユーザーフロー（goal-report-day-detail / issue #76）

目標レポート画面（`server/static/js/goals.js` の `renderReport`）だけを歩く。
**題材**：目標「メンタルを安定させる」の Day 31/32 レポートを開き、途中でスマホを見過ぎて
振り返りを書けなかった日（Day 15）に気づき、後から埋める。

タブ構成（現状・変わらない）：`今日` / `振り返り` / `カンバン` / `目標` / `設定`

今回入るのは①達成カレンダーへの**2つの見かた**だけ：
**ホバー**＝軽いプレビュー（ネットワーク往復なし）、**クリック**＝日別詳細モーダル（振り返りを編集できる）。
①のマス目そのもの・②〜⑤・沿革・目標時間・完走フォークは**一切変更しない**。

❓ は「まだ決まっていない・要判断」の印。

---

## いま何が起きていないか（変更前）

1. 目標タブ：レポートを開く。①達成カレンダーに「やった／やってない」のマス目が並ぶ
2. マスをクリックすると、④「毎日の日記」までスクロールし、その日の**文面だけ**が読める
   （気分・時間の内訳・ルールの達成理由は、①のマスと④のテキストに散らばったまま突き合わせられない）
3. 「この日は振り返りを書いたっけ？」を確認するには、**1マスずつクリックして④を読みに行く**しかない
4. ④は**読み取り専用**。書き忘れに気づいても、その場では直せず、振り返りタブへ移動する必要がある

> **変更点**：①のマスに**ホバー**すると軽いプレビューが出て、書いたかどうかが一目で分かる。
> **クリック**すると、その日の全体像（内訳・ルール状況・気分・振り返り）をモーダルで見られ、
> **振り返りはその場で直せる**。

---

## マスにカーソルを合わせるとき（ホバープレビュー）

*（★新規。ネットワーク往復なし。①のマスを何度なぞっても通信は発生しない）*

1. 目標タブ：レポートの①で、Day 15 の列（どのルールの行でもよい）にカーソルを乗せる
2. 軽いツールチップが出る：
   ```
   ┌─────────────────────┐
   │ Day 15 (2026-06-25)  │
   │ 未記入               │
   └─────────────────────┘
   ```
3. 隣の Day 16 に移すと、書いてある日はこう出る：
   ```
   ┌─────────────────────────────────┐
   │ Day 16 (2026-06-26)               │
   │ 今日は少し持ち直した。作業も…    │
   └─────────────────────────────────┘
   ```
4. マウスを外すとツールチップは消える。クリックはしていないので何も開かない

> **データは新規取得しない。** レポート取得時に④が使っているのと同じ
> `rep.days[dayNumber-1]`（目標日記→振り返りの日単位フォールバック済みテキスト）を
> そのままツールチップに出すだけ。書いたか／書いていないかを**1マスずつ高速に走査できる**ことが眼目で、
> 「スマホを見過ぎて振り返りできなかった日」を後から捜すユースケース（issue #76 コメント）はここで解ける。
>
> ヘッダの Day 番号（`.gr-cal-dh`）にカーソルを合わせても同じツールチップが出る。

## マスをクリックするとき（日別詳細モーダル）

*（★新規。①からの遷移なしで、その日の全体像を見る）*

1. 目標タブ：Day 15 のマス（またはヘッダの `15`）をクリックする
2. **既存どおり**、④の日付セレクタが Day 15 に切り替わり、①のマス・ヘッダがハイライトされる
   （ここは変更しない）
3. **加えて**、モーダルが開く：
   ```
   ┌─ Day 15（2026-06-25）───────────────────────────────┐
   │                                                      │
   │  この日にやったこと                                   │
   │    ⏱ 総作業時間     3h12m / 4h            未達         │
   │    ☑ 今日の振り返り  ✗                                │
   │    ☑ 明日のタスク登録 ✓                               │
   │    ☑ 筋トレ         ✗                                │
   │                                                      │
   │  時間の内訳                                           │
   │    SNS                    1h50m ▓▓▓▓▓▓▓▓            │
   │    競技プログラミング      1h22m ▓▓▓▓▓                │
   │                                                      │
   │  気分・振り返り                                       │
   │    気分  😞 😕 😐 🙂 😄   ← 未選択                    │
   │                                                      │
   │    ┌────────────────────────────────────────────┐    │
   │    │（本文なし）                                  │    │
   │    └────────────────────────────────────────────┘    │
   │                                                      │
   │                          [ 閉じる ]  [ 保存 ]        │
   └──────────────────────────────────────────────────────┘
   ```
4. 「この日にやったこと」は①のマスと同じ事実（met/未達）を、ルール名つきで並べただけ
5. 「時間の内訳」は、その日にどのタブグループに何時間使ったかを実測どおり出す
   （目標に紐づくルールに限らない。目標時間があれば、対象グループの実測をその日の目標時間の
   1日ぶんと比べて表示する ❓）

> **モーダルは既存の①クリック挙動を置き換えない。** ④の選択・ハイライトは今までどおり動き、
> モーダルはその上に**追加で**開くだけなので、既存の動線を壊さない。

## 振り返りをその場で埋めるとき

*（★issue #76 コメント本文：「振り返りはあとから編集することもできる」）*

1. モーダル：気分の 5段階から **🙂** を選ぶ
2. モーダル：本文欄に書く
   ```
   スマホを見すぎて何も手につかなかった日。反省。
   ```
3. モーダル：**「保存」**を押す → 保存成功のトーストが出て、モーダルが閉じる
4. 目標タブ：レポートが**再取得され再描画**される。①の見た目（マス目自体）は変わらないが、
   Day 15 にホバーすると今書いた文面がプレビューに出るようになり、
   ④の日付セレクタを Day 15 にするとその本文が読める

> **保存は既存の `振り返り` をそのまま更新する。** 振り返りタブの本文・気分と**同じデータ**であり、
> 別の下書きを持たない。保存後にレポートを丸ごと再取得するのは、①④のどちらの表示にも
> 差分更新のバグを持ち込まないため（単純さ優先）。
>
> **編集できるのは「振り返り」だけ。** この目標に**目標の日記**（`goal_journal`）が別に
> 存在する日は、モーダルの下に読み取り専用で注記が出る：
> ```
> 📔 この目標の日記（読み取り専用）
>    今日は運動を優先。日記のほうにまとめて書いた。
> ```
> ④が journal を優先して表示するのと同じ理由（目標日記と振り返りは別物）で、
> **モーダルから目標日記を編集する手段は今回作らない**（既存どおり振り返りタブ／目標コーナーから編集）。

## デモモードで開くとき

*（★閲覧専用の原則を守る）*

1. デモ／目標タブ：レポートの①で Day 15 に**ホバー**する → 通常どおりプレビューが出る
   （`rep.days` はデモの report レスポンスにも含まれているため、そのまま動く）
2. デモ／目標タブ：Day 15 を**クリックする** → **モーダルは開かない**。
   既存どおり④の選択・ハイライトが切り替わるだけ

> デモは仮想日付・専用DBで動いており、時間の内訳・振り返りの取得/保存は
> 本番用の `GET /api/summary` ／ `GET/PUT /api/reflection/:date` を素通りできない
> （デモ側に同等のエンドポイントが無い）。**無理に対応させず、クリックのモーダルはデモでは出さない**。
> ホバーはデータを新規取得しないので、デモでも制限なく動く。

## 今回やらないこと

- ①達成カレンダーの見た目・マス目グリッドの再設計（据え置き）
- 目標日記（`goal_journal`）をモーダルから編集すること（既存どおり振り返りタブ／目標コーナーのみ）
- 複数日をまとめて振り返る一括編集
- 未来日・凍結日・対象外日への特別な制限（既存の①クリック挙動をそのまま踏襲。未来日を開いても記録が無いだけ）
- デモモードでのモーダル対応（ホバーのみ）
- 通知・リマインダー（「書いていない日がある」を能動的に知らせる機能は別issue）

## 決まったこと

- **ホバー**：`rep.days[dayNumber-1]` の既存テキストをそのままツールチップに出す。**新規のネットワーク取得をしない**
- **クリック**：既存の④選択・ハイライトは維持したまま、**追加で**日別詳細モーダルを開く
- モーダルは3ブロック：**この日にやったこと**（ルール達成状況）・**時間の内訳**（`GET /api/summary`）・**気分・振り返り**（`GET/PUT /api/reflection/:date`）
- 編集できるのは**振り返り（気分・本文）だけ**。目標日記が別にあれば読み取り専用で注記する
- 保存後は**レポート全体を再取得して再描画**する（差分更新はしない）
- **デモモードではクリックのモーダルを出さない**（ホバーのみ動く）
- 新規のDB・APIは無し。既存の `GET /api/summary`・`GET/PUT /api/reflection/:date` を再利用する

## 未決の❓一覧

- ❓ 「時間の内訳」で、目標時間の対象グループがあるとき、その日の実測を**その日1日ぶんの目標時間**
  （`secondsPerDay`）と比べて表示するかどうか。素直に足せるが、期間平均の目標を1日で切り取って
  比べることの意味（「今日単体で見た目標時間の達成/未達」）をどこまで前面に出すかは使ってみないと分からない。
  **当面は出す**（②のグラフに既に同じ水準線があるので、認知の飛躍は無いと判断）
