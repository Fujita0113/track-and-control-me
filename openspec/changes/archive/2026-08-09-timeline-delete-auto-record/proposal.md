## Why

タブグループを閉じ忘れて放置すると、実際には作業していない時間が自動記録として計上され続ける。現在この自動記録ブロックはユーザーが取り消す手段が一切なく（詳細ポップオーバーは「自動記録ブロックは削除できません。」と表示するのみ）、誤った実績が集計・解錠ルール評価・振り返りへそのまま流れ込む。

記録を「消す」方向の操作は自分の実績を増やせないため、ずるの余地を作らずに誤記録を訂正できる（issue #90）。記録が信用できないと PDCA ループそのものが機能しなくなるため、訂正手段は計測の前提条件にあたる。

## What Changes

- タイムラインの自動記録ラン／ブロックの詳細ポップオーバーに **「この記録を削除」** 操作を追加する。誤操作を避けるため確認ステップを挟む。
- 削除は `session` 行の物理削除ではなく、**除外レコード（identity ＋ 時間区間）の永続化**として実装する。`recompute()` は `raw_sample` からセッションを毎回作り直すため、行を消すだけでは次の再集計で復活してしまう。
- 除外は集計の入口（`aggregateSamples`）で「そのグループは当該区間に開いていなかった」ものとして適用する。したがって:
  - 同時オープンだった他グループが残る区間は、残りのグループで **divide-by-N を N−1 へ再按分**する（開きっぱなしによる過小計上が直る）。区間の総計上時間は増えない。
  - 開いていたグループが全て除外された区間は、`ungrouped` へ落とさず**未計上（除外時間）**として扱う。タイムライン上は未記録ギャップとなり、既存のゴーストスロットから手動で記録し直せる。
- **確定済み（`is_final=1`）の過去日も削除できる**。対象日に限って確定ガードを外して再集計し、その日のルール評価も再実行する。削除は時間を減らす方向にしか働かないため、確定日の実績が増えることはない。
- 除外レコードは復元可能な形（区間と identity を保持）で残し、削除直後のトーストから取り消せる。

**BREAKING** なし（既存 API・スキーマの互換は維持し、テーブルと集計引数を追加する）。

## Capabilities

### New Capabilities
- `timeline-record-deletion`: 自動記録ブロックの削除（除外レコードの永続化、再集計をまたいだ持続、同時オープン時の再按分、全除外区間のギャップ化、確定日の訂正、取り消し）

### Modified Capabilities
- `timeline-run-view`: 詳細ポップオーバーの要件に、自動記録ラン／ブロックの削除導線（確認ステップ込み）を追加する

## Impact

**サーバ（データ層）**
- `server/src/db/migrations.ts`: 除外レコードのテーブルを追加
- `server/src/aggregation/aggregate.ts`: `aggregateSamples` が除外リストを受け取り、区間ごとに open グループから除外・全除外時は非計上（新しい除外理由）へ回す
- `server/src/services/recompute.ts`: 除外レコードの読み込みと identity 解決、確定日を対象にした強制再計算
- `server/src/rules/evaluate.ts`: 確定済み日の強制再評価

**サーバ（API）**
- `server/src/api/timeline.ts`: 自動記録の削除／取り消しエンドポイント
- `server/src/services/timeline.ts`: 除外レコードの作成・取り消し

**クライアント**
- `server/static/js/timeline.js`: 詳細ポップオーバーの削除導線（`runBreakdown` の「削除できません」表示を置換）
- `server/static/js/api.js`: 対応する API クライアント
- `server/static/css/app.css`: 確認ステップ用のスタイル（1ルール1行の既存書式を維持）

**波及先（値が変わりうる読み取り経路）**
- `daily_totals_snapshot` → `categories.ts`（総作業時間）→ 解錠ルール評価 → 目標の達成日数・完走レポート
- `session` → タイムライン、`today-group-breakdown`、振り返りリボン、`day-allocation`
