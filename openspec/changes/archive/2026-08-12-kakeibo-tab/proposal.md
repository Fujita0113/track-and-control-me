## Why

家計簿が要る（issue #94）。だが要るのは「金額の台帳」ではなく、**今月このままだといくらで着地するか**である。

#94 は当初「直近3〜5回の平均から日単価を出す」と書いており、最初の設計はそれを一般化して
「その買い物が実際に何日もったか」を聞き、名称ごとに日単価を持つモデルにした。
issue のコメントでこれは**取り下げられている**:

> 一ヶ月に一度とか、急な出費とかそこら辺は除外して、あとはコンビニだろうがなんだろうが
> 単純に 30/現在の日数でかけてあげれば予想になるか。複雑なロジック組みすぎた。

つまり予想は **今月これまでの出費 ÷ 経過日数 × 月の日数** の一本でよい。日数を聞く必要が無くなり、
名称ごとの基準も、実績日数の確定も、カバー期間の帯も、まとめて要らなくなる。
残る唯一の調整弁は「**この出費は毎月は起きないので平均に混ぜない**」という指定だけである。

単純な平均単価は月前半のまとめ買いを月末まで引き伸ばすので**上振れする**。これは方式の性質であり、
隠さずに受け入れる。画面は月末予想と超過を常時見せ、途中式（÷経過日数）と調整はモーダルへ畳む。

そして「毎日ちゃんと付ける」ことを支える仕掛けは、このアプリに既にある。解錠ゲートに1条件足せばいい
（#94 の「パスワードで管理したい」）。LLM との振り返りは #94 の記述どおり**今回は作らない**。

`ref/kakeibo/kakeibo-mock.html`（5巡目・スクショ10枚）が**この変更の仕様である**。

## What Changes

- **家計簿タブを新設**する。トップタブは `今日 / 振り返り / カンバン / 目標 / 家計簿 / 設定` の6本になり、家計簿の中に **ホーム / 履歴 / 分析 / 予算** の4サブタブを置く。
- **支出レコード**を導入する。項目は `名称 / 金額 / カテゴリ（食品・日用品・娯楽・急な出費）/ 重要度（必須・準必須・無駄遣い）/ 計算対象 / 内訳（任意）/ レシート（任意）`。名称は履歴からサジェストして使い回す（#94）。**日数は持たない。**
- **月末予想**を出す。`1日平均 = floor(日々の出費 ÷ 経過日数)` を残り日数へ掛けるだけ。折れ線は `固定費（切片）＋ 実績（階段）＋ 予想（一定勾配の破線・段＝予定出費）` で、上限線との交点日を示す（「このペースだと 8/23 に上限超過」）。
- **特別費**を導入する。特別費に指定した額は**実績には残り、1日平均の母数からだけ抜ける**。カテゴリ `急な出費` は自動で特別費になり手では戻せない。それ以外は手動で切り替える。ホームの「予想の計算内訳・調整」で切り替えると **計算対象・1日平均・月末予想・超過日** が保存せずその場で出し直され、履歴の行の二択はその場で保存される。
- **内訳**を任意で書けるようにする（#94 の「レシートはないけど何を買ったのか覚えているとき」）。自由記述で、システムは解釈しない。**見る場所はレシートと同じ**＝明細を押すと内訳とレシートが別々の面で並ぶ。履歴の行からも分析の明細からも同じ画面が開く。
- **予算**を持つ。月の上限 → 固定費の予想を引いて変動費に使える額 → **週の目標**へ割る（#94 の「月あたりの目標を週あたりに置換」）。固定費の予想は**先月の実績から取り込む**（#94 の「電気代が先月いくらだったから」）。
- **毎月の予定出費**（床屋 30日ごと・次は 8/20 等）を持つ。**予想にだけ入り、実績にはならない**。
- **未記録期間の一括入力**（#94 の「長い間未記録だったとき」）。`8/2–8/5 まとめ ¥3,400` のように期間と総額だけを1件で埋める。重要度を持たず、分析では `内訳未入力` として区別し、名称別の割合分析の母数から外す。
- **分析**は `カテゴリ → 名称 → 明細` の3段ドリルと重要度の帯。棒は全段で同じ ¥ スケール、`%` は一段上に対する割合。**円グラフは使わない**（#94 は円グラフを挙げていたが、割合の比較には長さのほうが読める）。
- **履歴は一覧だけ**にする。グラフ・帯は置かない（推移はホームの折れ線が担う）。行は「左＝明細を開く / 右＝特別費の二択」の2領域。
- **解錠ゲートに「家計簿に今日の記録がある」を足す**。`PLANNING` の新シグナル `kakeibo_recorded` として既存レジストリに載せるので、ルールの作成・編集・沿革・latch は全部既存経路に乗る。使わなかった日のために **「0円だった」宣言**を用意する。
- **スコープ外**: LLM との振り返り（#94 が明示的に後回しにしている）／収入・資産・口座残高／複数通貨／レシートの OCR・自動読み取り／家計簿データの外部同期／**日数の在庫と名称ごとの日単価**（issue コメントで取り下げ）。

## Capabilities

### New Capabilities

- `kakeibo-ledger`: 支出レコードそのもの（項目・カテゴリ・重要度・内訳・名称サジェスト・月の区切りと月ナビ・まとめ登録＝内訳未入力・レシート添付・履歴の一覧と行の2領域）
- `kakeibo-forecast`: 月末予想（1日平均ひとつ・特別費の自動/手動判定と保存しない再計算・折れ線・上限超過日・4成分の1行サマリ・今週の残り予算・「無駄遣い」の上限）
- `kakeibo-budget`: 予算（月の上限・週の目標への割り付け・固定費の予想と先月からの取り込み・「無駄遣い」の上限・毎月の予定出費）
- `kakeibo-analysis`: 分析（重要度の帯・カテゴリ→名称→明細の3段ドリル・明細からの内訳とレシートの閲覧）
- `kakeibo-gate`: 解錠ゲートへの合流（何をもって「今日の記録がある」とするか・「0円だった」宣言・今日タブからの導線）

### Modified Capabilities

- `kanban-rule-conditions`: `PLANNING` のシグナルレジストリに `kakeibo_recorded` を追加する（ルール編集の条件ドロップダウンにも1項目増える）
- `demo-mode`: デモのサンプルに家計簿の1か月分を加える（モックの筋書き＝上限超過が見えている月）
