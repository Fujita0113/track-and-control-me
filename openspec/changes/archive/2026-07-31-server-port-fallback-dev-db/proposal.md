## Why

現状、ダッシュボードを使うには毎回手動で `npm run server` を実行する必要がある(issue #13
タイトル)。加えて `server/.env` は DB 接続先を常に「本チェックアウトの実 DB」に固定して
おり、この設定は tracked ファイルのため `git worktree add` した worktree にもそのまま
コピーされる。そのため worktree で `npm run server` すると常に本物の実データベースに
繋がってしまう。さらに、いつも使うポート(既定 47653)が既に他プロセスに使われていると
`npm run server` はポート衝突でクラッシュし、worktree での動作確認ができない(issue #13 本文)。

この2つは1つの解決策でつながる: 本チェックアウトのサーバーを Windows ログオン時に自動起動
しておけば、いつものポートは常に本チェックアウトが握っている状態になる。その状態で
worktree から `npm run server` すれば、それは自然に「別プロセス・フォールバックポート・
開発用 DB」という扱いになり、実行のたびに `npm run server` を手打ちする手間も、本チェック
アウト側のプロセスを止める手間も要らなくなる。

## What Changes

- Windows ログオン時にサーバーを自動起動する(タスクスケジューラ登録、`npm run server` を
  手動実行しなくてもダッシュボードが立ち上がっている状態にする)。
  - 非表示(バックグラウンド、コンソールウィンドウを出さない)で起動する。
  - リポジトリに同梱するセットアップスクリプト(PowerShell)を一度実行すればタスク
    スケジューラに登録される。追加の npm 依存は増やさない。
  - 再実行しても安全(冪等。既存の登録は上書きし、重複登録しない)。
  - 併せてアンインストール用スクリプトも用意する。
- サーバー起動時、設定ポート(env > `config.local.json` > 既定 47653)が使用中なら
  base+1, base+2, ... と空きポートを自動探索してそちらでリッスンする(既存プロセスを
  止めなくてもクラッシュせず立ち上がる。自動起動している本チェックアウトのプロセスと、
  worktree から手動で起動するプロセスが共存できる)。
- DB 接続先の解決順位を変更する:
  1. `DB_PATH` 環境変数 / `config.local.json` の明示指定(最優先、既存どおり)
  2. 明示指定が無い場合:
     - 実際にバインドできたポートが「いつものポート」と一致 → 従来どおり
       `<serverRoot>/data/track.sqlite`(実 DB)
     - ポートフォールバックが発生した(いつものポートが使えなかった＝別プロセスとして
       起動した) → `<serverRoot>/data/track.dev.sqlite`(隔離された開発用 DB)を使う
- **BREAKING**: `server/.env` の `DB_PATH` ハードコード行を削除する。これにより worktree で
  明示指定なしに `npm run server` した場合、従来の「本チェックアウトの実 DB に繋がる」挙動
  ではなく「自ディレクトリ配下の DB を使う」挙動に戻る(安全側)。本チェックアウト側の通常起動
  (いつものポートが空いている場合)の結果は変わらない。
- 開発用 DB (`track.dev.sqlite`) を新規作成したときに限り、カンバンタスクや長期目標など
  最小限のテストデータを投入する(空のダッシュボードではなく触って確認できる状態にする)。
  既に存在するファイルには重ねて投入せず、リセットもしない(毎回同じ開発用データを使い
  回してテストする用途のため)。
- 起動時にバインドされたポート番号(と、いつものポートからフォールバックしたかどうか・
  どちらの DB に繋がっているか)を `npm run server` の出力ではっきり分かる形で表示する。

## Capabilities

### New Capabilities
- `server-port-fallback`: サーバー起動時のポート自動フォールバック、フォールバック時の
  開発用 DB への自動切替とテストデータ投入、起動ポートの可視化を扱う。
- `server-autostart`: Windows ログオン時の非表示自動起動と、そのセットアップ/解除手順を扱う。

### Modified Capabilities
(なし。既存の spec 化された capability の要件変更はない)

## Impact

- `server/src/config.ts`: ポート探索・DB パス解決ロジックの追加(既存の `loadRuntimeConfig`
  を、ポート確定前後で呼び分けられる形に分割)。
- `server/src/main.ts`: 起動シーケンスを「空きポート探索 → DB オープン(必要ならテストデータ
  投入) → ルート登録 → listen」の順に組み替え。起動ログの追加。
- `server/.env`: `DB_PATH` 行を削除。
- 新規: `server/src/services/dev-seed.ts`(仮) — 開発用 DB 初回作成時のテストデータ投入。
- 新規: `server/scripts/register-autostart.ps1` / `unregister-autostart.ps1` / 非表示起動用
  ランチャー(vbs) — タスクスケジューラへの登録・解除。
- 影響なし: 拡張機能(extension)側。拡張は固定ポートに接続する前提のままで良い。
