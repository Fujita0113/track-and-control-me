# ユーザーフロー（goal-target-hours-and-open-period / issue #76）

実際の画面（タブ）を歩く。**題材は issue #76 のコメントに書かれたものをそのまま使う**：

いま持っているルールを全部ぶち切って、次の2つを並行で立てる。

| | 目標A | 目標B |
|---|---|---|
| 名前 | アルゴリズムを固める | 試験期間の筋トレ |
| **目標とする状態** | アルゴリズムを一通り自力で実装できるようになっている | 試験直前になってもちゃんと筋トレに行けていること |
| **目標時間** | `アルゴリズム` or `Python` グループ **合計 2時間 / 日** | **なし** |
| **証拠写真** | キャプション「AtCoder レーティング」・初期写真あり | **求めない** |
| 下限（パスワードの条件） | 同グループ 15分 / 日、総作業時間 4時間 / 日 | ☑ ジムに行った |
| 期限 | **8/6 まで**（今日 8/1 から6日間） | 8/6 まで |

タブ構成（現状・変わらない）：`今日` / `振り返り` / `カンバン` / `目標` / `設定`

**目標Bが「目標時間も証拠写真も持たない目標」の実例**である（ルックス改善・掃除もこの形）。
目標時間も証拠写真も**任意**であり、無い目標はその表示が出ないだけで、他はすべて同じように動く。

❓ は「まだ決まっていない・要判断」の印。

---

## いま何が起きていないか（変更前）

1. 目標タブ：「＋ 新しい目標」を押すと、期間は **30日固定**。それ以外を選べない
2. 目標タブ：カードは `[Day 12/30]`・目的の一文・ルールのチップが並ぶだけ。
   **いま何時間で、あと何時間必要なのかは、どこにも書いていない**
3. 目標タブ：始めた目標は **完走まで終われない**（削除できるのは作成当日だけ）。
   「もう試験勉強は大丈夫だから切り替えたい」ができない
4. 目標タブ：**目標をまたぐ歴史が無い**。沿革は1つの目標の中のルール操作だけ

> **変更点**：①期限を自由に決められる ②目標時間とペースがカードに出る
> ③いつでも理由つきで終われる ④目標タブの下に「大きい沿革」（目標の年表）が出る

## 目標を作るとき

*（既存フローに、目標時間と期限が入る）*

1. 目標タブ：「＋ 新しい目標」を押す
2. 目標タブ：フォーム
   ```
   ┌─ 新しい目標 ──────────────────────────────────────────────┐
   │                                                           │
   │  名前（必須）    [ アルゴリズムを固める              ]     │
   │                                                           │
   │  めざす状態（必須）                                        │
   │  ┌───────────────────────────────────────────────────┐    │
   │  │ アルゴリズムを一通り自力で実装できるようになっている │    │
   │  └───────────────────────────────────────────────────┘    │
   │    ↑ 終わるときに「これができたか」を聞かれます            │
   │                                                           │
   │  なぜ始めるのか（必須）                                    │
   │  ┌───────────────────────────────────────────────────┐    │
   │  │ 試験前だが手は止めたくない                          │    │
   │  └───────────────────────────────────────────────────┘    │
   │                                                           │
   │  証拠写真（任意）                                          │
   │    ☑ 終わるときに写真を出す                                │
   │      キャプション [ AtCoder レーティング          ]        │
   │      いまの写真（任意）  ＋ 写真を追加                     │
   │        ┌────────┐                                        │
   │        │ [画像] │  ← 置かなくてもよい                     │
   │        └────────┘                                        │
   │                                                           │
   │  いつまで                                                 │
   │    開始  ● 今日から   ○ 明日から                          │
   │    期限  [ 2026-08-06 ]      （ 1週間 / 2週間 / 30日 ）    │
   │                                    ↑ よく使う長さのボタン  │
   │                                                           │
   │  目標時間（任意・パスワードの条件にはなりません）          │
   │    ● グループ  [ アルゴリズム ×] [ Python ×] [＋]         │
   │      ○ 総作業時間    ○ カテゴリ                           │
   │    合計  [ 2 ] 時間  / 日                                 │
   │                                                           │
   │  下限（毎日・パスワードの条件になります）      [＋ 追加]   │
   │    ⏱ グループ アルゴリズム   15分 / 日                 −  │
   │    ⏱ 総作業時間             4h  / 日                   −  │
   │                                                           │
   │                            [ やめる ]  [ 作成 ]           │
   └───────────────────────────────────────────────────────────┘
   ```
3. 目標タブ：「作成」→ 一覧にカードが現れる。置いた初期写真は Day1 に保存される

> **変更点①：期限が自由になる。** これまでは開始日を選ぶだけで期間は30日固定だった。
> 今回は期限の日付を直接入れる（1週間・2週間・30日のボタンは入力補助にすぎない）。
> **「1週間の目標」も「6日の目標」も、専用の機能なしに作れる**（issue #65 もこれで満たす）。
>
> **変更点②：目標時間が入る。** 「1日あたり何時間」を1目標につき最大1つ持てる。
> **複数のグループを束ねられる**（`アルゴリズム` or `Python` の合計で2時間）。
> **目標時間はパスワードの条件にならない。** 平均は日次では判定できない（その日が終わるまで確定しない）ので、
> そもそもゲートに乗せられない。判定できないものは強制しない、というのが分け方の理由。
>
> **目標時間は任意。** 目標B（筋トレ）のように入れなくてよい。
>
> **「なぜ始めるのか」は必須。** このアプリではルールの追加・変更・削除がすべて理由必須なので、
> 目標そのものにも同じ扱いをする。**終えるときの理由と対になって**大きい沿革に並ぶ：
> `＋作成 ― 試験前だが手は止めたくない` / `−終える ― 試験勉強はもう大丈夫。設計に切り替えたい`。
> 「めざす状態」が **何** を、「なぜ始めるのか」が **いま何故** を担う。
>
> **変更点③：証拠写真を「求めるかどうか」を最初に決める。**
> ☑ を入れるとキャプションを1つ決める。ここで決めたキャプションが、
> **終わるときに出す写真の宛先**になり、そのまま**レポート③の Before/After のグループ**になる。
> **初期写真（Before）は置いても置かなくてもよい**。置けば Day1 に保存され、
> 置かなければ終わるときの1枚だけが残る。
> 求めない設定（目標B）なら、この欄も終わるときの問いも現れない。

4. 目標B も同じフォームで作る。目標時間の欄と証拠写真の ☑ は空のまま、下限に `☑ ジムに行った` を入れる

## 目標タブを開くとき（★今回の中心）

1. 目標タブ：カードを開いた瞬間に、**いま何時間で、あと何時間必要か**が読める
   ```
   進行中
   ┌──────────────────────────────────────────────────────────┐
   │ アルゴリズムを固める                                      │
   │                              [Day 4/6]  [ レポートプレビュー ]│
   │ めざす状態： アルゴリズムを一通り自力で実装できるように     │
   │              なっている                                   │
   │ 2026-08-01 〜 2026-08-06                                  │
   │                                                          │
   │  目標時間  アルゴリズム ／ Python   合計 2時間 / 日        │
   │    いま   平均 1h24m / 2h                                │
   │    ▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░                                 │
   │    今日 あと 3h48m で到達                                 │
   │                                                          │
   │  下限   ⏱ アルゴリズム 15分   ⏱ 総作業時間 4h            │
   │                                        [ 終える ]        │
   └──────────────────────────────────────────────────────────┘
   ┌──────────────────────────────────────────────────────────┐
   │ 試験期間の筋トレ                                          │
   │                              [Day 4/6]  [ レポートプレビュー ]│
   │ めざす状態： 試験直前になってもちゃんと筋トレに行けている   │
   │              こと                                         │
   │ 2026-08-01 〜 2026-08-06                                  │
   │                                                          │
   │  下限   ☑ ジムに行った                                    │
   │                                        [ 終える ]        │
   └──────────────────────────────────────────────────────────┘
   ```

2. **「今日 あと 3h48m で到達」が毎日変わる**
   ```
   計算 ： 必要累計 = 目標時間 × 経過日数（開始日から今日まで・今日を含む）
           今日あと = max(0, 必要累計 − 現在の累計)   ← 累計は今日の実測を含む

   例   ： 目標 2h/日、Day 4、Day1〜3 の累計 4h、今日ここまで 12m
           必要累計 = 2h × 4 = 8h
           現在累計 = 4h12m
           今日あと = 3h48m
   ```
   昨日やれば今日は軽くなり、サボれば今日が重くなる。**今日という日に固有の意味が乗る**

3. 到達していれば `✓ 到達` に変わり、必要量の数字は出さない（追い立てない）
4. **目標B にはこのブロックが出ない**（目標時間が無いので）。カードの他の部分は同じ

> **変更点④：目標時間を持たない目標は、ペース表示が出ないだけ。** 特別扱いも例外分岐も無い。
> 「ルックス改善のレポートをどうするか」（issue #76 コメント）の答えはここで、
> **目標時間が任意である**以上、決めることは何もない。
> 目標Bのレポートは、既存の①達成カレンダー・③Before/After・⑤沿革がそのまま担う。

## 今日タブを開くとき

1. 今日タブ：一番上に1行だけ出る
   ```
   ┌──────────────────────────────────────────────────────────┐
   │ ▸ アルゴリズム／Python  平均 1h24m / 2h                   │
   │   今日 あと 3h48m で到達                     目標タブへ → │
   └──────────────────────────────────────────────────────────┘
   ┌──────────────────────────────────────────────────────────┐
   │  4h 12m                                                  │
   │  総作業時間 (2026-08-04)         ← 以下、既存のまま        │
   └──────────────────────────────────────────────────────────┘
   （グループ別ドーナツ／直近7日の棒／🔒 解錠状態／条件の進捗／パスワード）
   ```
2. 目標時間を持つ進行中の目標が複数あれば、その数だけ行が並ぶ。1つも無ければ何も出ない
3. 押すと目標タブへ飛ぶ

> **今日タブは導線に徹する。** 本体は目標タブ。
> 「全然開かない長期目標タブからしか振り返れない」（issue #76 本文）を、
> **毎日必ず開く場所に入口を置く**ことで解く。
> 既存のゲート表示・条件の進捗・パスワード動線は一切変えない。

## 途中でやめるとき（未達でも終われる）

*（★「試験勉強はもう大丈夫だから、もっとやりたいことをしたい」）*

1. 目標タブ：カードの **「終える」** を押す
2. 目標タブ：**3つ**を聞かれる（理由だけが必須）
   ```
   ┌──────────────────────────────────────────────────────┐
   │  「アルゴリズムを固める」を終えますか？               │
   │  期限（8/6）より前ですが、いつでも終えられます。      │
   │                                                      │
   │  めざした状態はどうでしたか？（任意）                 │
   │    アルゴリズムを一通り自力で実装できるようになっている│
   │      ○ できた    ● できなかった    ○ 答えない        │
   │                                                      │
   │  証拠写真（任意）                                     │
   │    キャプション「AtCoder レーティング」               │
   │      ＋ 写真を出す      ← 後からでも出せます          │
   │                                                      │
   │  理由（必須）                                         │
   │  ┌────────────────────────────────────────────────┐  │
   │  │ 試験勉強はもう大丈夫。設計に切り替えたい         │  │
   │  └────────────────────────────────────────────────┘  │
   │                                                      │
   │              [ やめておく ]      [ 終える ]           │
   └──────────────────────────────────────────────────────┘
   ```

   > **めざした状態の問いは3値**（できた／できなかった／答えない）で、**必須にしない**。
   > 「一通り実装できるようになったか」は白黒つかないことがあり、
   > 強制すると嘘の自己申告になる。**答えないことも事実として記録する。**
   >
   > これは**本人の自己申告であって、システムの採点ではない**（既存の `☑ 手動チェック` と同じ名誉ベース）。
   > 「できなかった」に赤・バツ・否定的な装飾を付けてはならない。
   >
   > 証拠写真は作成時に決めたキャプションで保存され、**レポート③の After になる**。
   > ここで出さなくても、後から振り返りタブの目標コーナーで出せる。
   > 作成時に「求めない」にした目標（目標B）には、この欄そのものが出ない。

3. 「終える」→ **当日から**効く
   - この目標の永続ルール（下限）が**その日のゲートから外れる**
   - 目標は「終了」としてアーカイブされ、**レポート・沿革・カレンダーは読めるまま残る**
   - 理由・めざした状態の答え・証拠写真が **⑤沿革の最終エントリ**と、下の**大きい沿革**に残る
4. 目標タブ：終わったので、新しい目標をその場で作れる

> **完走したときも同じ。** 完走フォークの「終える」を選んだ場合も、
> 途中で終えた場合と同じ問い（めざした状態・証拠写真・理由）を出し、同じく**当日から効く**。分岐を作らない。

> **変更点⑤：完走を待たずに終われる。** これまで「終える」は完走後のフォークからしか押せず、
> 途中で降りる手段は「作成当日の削除」だけだった。
> 今回、いつでも理由つきで終えられる（**理由は必須**。完走フォークの任意から昇格させる）。
>
> **当日から効く。** 既存の `editable-rule-registry`「ルールはいつでも追加・変更・削除でき**当日から効く**」と
> 同じ形にそろえる。目標を終えることは、その目標の永続ルールをまとめて削除することに等しいので、
> 単体のルール削除が当日効くのに目標終了だけ翌日、というのは筋が通らない。
>
> **抑止は「歴史が汚れること」が担う。** 今日のゲートを回避するために目標を終えれば、
> **その事実と理由が大きい沿革に永久に残る**。仕掛けで塞ぐのではなく、逃げた事実そのものを記録に残す
> — これは既存の思想（凍結・理由つき緩和を「消してはならない」）とまったく同じやり方である。
>
> **期限の短縮は提供しない。** 短くしたいときは「終えて、作り直す」。
> `end_day` は前方向にのみ動く（既存 `goal-lifecycle-fork` の不変条件を壊さない）。

## 目標をまたいだ歴史を読むとき（大きい沿革）

*（★「レポートがたくさんある感じの画面の下に、目標の追加・消去・変更の歴史が欲しい」）*

1. 目標タブ：カード一覧の下までスクロールすると **「これまでの目標」** がある
   ```
   これまでの目標
   ──────────────────────────────────────────────────────────────────
    8/01 ＋ アルゴリズムを固める                      目標 2h/日
           めざす状態： アルゴリズムを一通り自力で実装できるように
                        なっている
           [Before]  AtCoder レーティング
           ― 試験前だが手は止めたくない

    8/04 − 終える  アルゴリズムを固める     × 平均 1h51m / 2h
           めざした状態： × できなかった
           [Before] → [After]  AtCoder レーティング
           ― 試験勉強はもう大丈夫。設計に切り替えたい

    8/05 ＋ 設計を固める                             目標 1h30m/日
           めざす状態： 設計を自分の言葉で説明できる
           ― 競プロより今はこっちに熱がある

    8/06 ✓ 完走  試験期間の筋トレ
           めざした状態： ✓ できた
   ──────────────────────────────────────────────────────────────────
   ```
2. 各行は **`day_key` 昇順（同日内は記録順）で決定的**に並ぶ
3. 行に載るのは **目標の作成・終了・完走**と、そのときの
   **理由（始めた理由／終えた理由）** ／ **目標時間の到達・未達** ／ **めざした状態の答え** ／ **証拠写真**
4. 行をクリックすると、その目標のレポートが開く
5. **未達には `×` が付く**。一目で「どこで届かなかったか」を拾えるようにする

> **ここが「大きい沿革」の主役。** 目標時間（数字）だけでは「2時間やったが、で？」に終わる。
> **めざした状態の答え**と**証拠写真**が並んで初めて、
> 「時間は足りなかったが状態には届いた」「時間は足りたが状態には届かなかった」が読める。
>
> `8/04` の行がその実例：**平均は未達、状態も「できなかった」、でも Before→After は残っている**。
> 数字・自己申告・写真の3つがそろって、はじめて事実になる。
>
> **`✓` / `×` は大きい沿革では付けてよい。** 目標に達しなかったなら原因があり、それを潰せばいいだけで、
> **判定は診断であって断罪ではない**（本人の言葉：「僕的には全然ポジティブな失敗判定」）。
> `×` が一目で拾えないと、沿革を眺めて次の一手を考えるという用途そのものが成立しない。
>
> ただし依然として出さないもの：**合格・不合格・スコア・ランク・点数・紙吹雪・バッジ**。
> 出すのは `到達 / 未達`・`できた / できなかった` という**事実の2値**と、それを見分けるための記号だけ。
> レポート①〜⑤・カード・今日タブでは従来どおり `×` を使わない（大きい沿革だけの扱い）。
>
> **既存の⑤沿革（`goal-chronicle`）とは別物。** ⑤は「1つの目標の中のルール操作と凍結の年表」で、
> 大きい沿革は「**目標そのものの年表**」。粒度が1段違う。
> どちらも「逃げた事実そのものを歴史に残す」という既存の思想に従い、**終えた事実を消してはならない**。

## 目標時間を持たない目標のレポートを開くとき

*（★issue #76 コメントで「全く決まっていない」とされていた点。決めることは無い、が答え）*

1. 目標タブ：目標B「試験期間の筋トレ」（目標時間なし・証拠写真なし）の「レポートプレビュー」
2. レポート：既存のヘッダ＋①〜⑤がそのまま出る
   - ①達成カレンダー … `☑ ジムに行った` の行が日ごとに並ぶ（既存）
   - ②時間の推移 … **時間型ルールが無いので、このブロックは出ない**（既存の仕様どおり）
   - ③Before/After … 写真ルールがあれば並ぶ（既存）
   - ④日記リーダー（既存）／⑤沿革（既存）
3. **目標時間があるとき**（目標A）は、②に目標時間の水準が加わる
   ```
   ② 時間の推移
      ── 実測（アルゴリズム＋Python の合計）
      ┄┄ 目標時間 2h/日      ← 新規。破線で1本引く
      ─  下限 15分/日        ← 既存の閾値表示
   ```

> **変更点⑥：レポート②に目標時間の線が1本増えるだけ。** 新しいブロックを足さない。

## 決まったこと

- **目標時間**を新設する。**1目標につき最大1つ・任意**。単位は **1日あたり**
- 目標時間の対象は **グループ（複数を束ねられる＝`or`）／総作業時間／カテゴリ**。時間型のみ
- **目標時間はパスワードの条件にならない**（MUST NOT）。日次で判定できないものはゲートに乗せない
- ペースは `必要累計 = 目標時間 × 経過日数（今日を含む）` から `今日あと` を出す。到達済みは数字を出さない
- **目標時間の到達判定は期間平均**（`平均 >= 1日あたりの目標`）。ペース表示と同じ式で一貫させる
- **目標時間の対象は作成時に固定**。途中で足す／外すことはできない。変えたいときは終えて作り直す
- **期限を作成時に自由に指定できる**。30日固定を撤廃する。1週間/2週間/30日は入力補助のボタン
- **期限に上限を設けない**。困ったときに足す
- **期限の短縮は提供しない**（既存どおり前方向のみ）。短くしたいときは「終えて、作り直す」
- **めざす状態**（従来の「目的の一文」）を**必須**にし、カードに常時表示する
- **「なぜ始めるのか」（作成理由）を新設し、必須**にする。終えるときの理由と対で大きい沿革に並ぶ
- **証拠写真を求めるかどうかを作成時に決める**。求めるならキャプションを1つ決め、**初期写真は任意**
- **終わるとき（途中終了・完走の「終える」の両方）に3つを聞く**：
  めざした状態の答え（**3値・任意**：できた／できなかった／答えない）・証拠写真（任意）・理由（**必須**）
- めざした状態の答えは**本人の自己申告**であり、システムは検証しない（写真も判定しない）
- **効くのは当日から**（既存の `editable-rule-registry`「当日から効く」にそろえる）。
  ゲート回避目的の終了は、**その事実が大きい沿革に残ること**が抑止を担う
- 終えた目標のレポート・沿革・カレンダーは**読めるまま残す**（消してはならない）
- **大きい沿革**（目標の年表）を目標タブのカード一覧の下に置く。載せるのは
  作成・終了・完走／始めた理由・終えた理由／目標時間の到達・未達／**めざした状態の答え**／**証拠写真**
- **大きい沿革では `✓` / `×` を使ってよい**。判定は診断であって断罪ではない。
  ただし合格・不合格・スコア・ランク・紙吹雪は出さない。`×` は大きい沿革のみの扱いとし、
  レポート①〜⑤・カード・今日タブには持ち込まない
- **今日タブは1行の導線**に徹する。既存のゲート表示は一切変えない
- 目標時間・証拠写真を持たない目標は**その表示が出ないだけ**。レポートも既存のまま。特別扱いをしない
- レポート②に**目標時間の線を1本**足す。証拠写真は既存の③（Before/After）へそのまま流入する
