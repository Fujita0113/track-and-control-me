## Why

長期目標をやるにあたって、やることを**分解したい**（issue #91）。「面接対策をする」は、そのままではカンバンに置けない。「苦手な質問への回答を用意する」→「面接対策2024を見ながら苦手な質問をピックアップする」→…と、**何階層になるか事前に分からない**深さで割っていって、初めて手が動く粒度になる。

いまのカンバンの `task` は完全にフラットで、親子の概念が無い。だから分解した結果を置く場所が無く、分解は頭の中か外部（Notion 等）に置き去りになり、実行（カンバン）と長期目標が繋がらない。逆に、分解した葉をそのままカンバンに流し込むと、文脈を失った断片が盤面に散らばる。

必要なのは**親タスク**の概念と、それを目標単位でひと目で見る**設計図**である。設計図で書いた葉が自動でカンバンに現れ、カンバンで完了させると設計図にチェックが付く。

## What Changes

- `task` に **`parent_task_id`（自己参照）・`goal_id`・`tree_order`** を追加し、**深さ無制限のタスクツリー**を導入する。目標に紐づかない普段のカンバンタスクも分解できる（ツリー機構自体は目標非依存）。
- **葉だけがカンバンのカードになる**。子を持つタスク（＝容れ物）は盤面に出ず、完了状態は子から**導出**される。
  - **BREAKING（既存の盤面挙動）**: カードを分解すると、そのカードは盤面から消えて子に置き換わる。子は親がいた列を引き継ぐ。**完了済みのタスクは分解できない**。
- 目標ごとの**設計図ビュー**を新設する。レポートとは**別のビュー**で、レポート画面（`goal-report` の5ブロック）には手を入れない。
  - **プレビュー**（折りたたみ可能なカードのツリー）と**取り込み**（テキスト貼り付け）を切り替える。
  - 既定の展開は「**現在地までのパスだけを開く**」。進行中の葉、無ければ未完了の最初の葉までの祖先を開く。
- **テキスト取り込みは一方向（追加のみ）**。インデントが階層、`-` 行がタスク、`-` の無い行が直前のタスクの本文（`task.notes`）。既存ノードを書き換えたり消したりしない。
- 枝ごとの **「この枝に着手する」**：配下の葉をまとめて `HOLD` から `TODO` へ送る。取り込み直後の既定は `HOLD` で、盤面が溢れないようにする。
- 盤面のカードに**親のパンくずチップ**を出す（`面接対策 › 苦手な質問への回答`）。分解した葉は単体では意味が読めないため。
- 枝を畳む **「この枝を打ち切る」**（理由つき）。親のチェックボックス自体は導出値で、手で付けられない。
- **PLANNING シグナルの修正**: 「翌日の未完了タスク数」の集計から容れ物タスクを除外する。容れ物が期限を持つとゲートの解錠条件が水増しされるため。

## Capabilities

### New Capabilities

- `task-tree`: `task` の親子関係そのもの（無制限の深さ、葉＝カード、容れ物の完了導出、循環の禁止、分解・再親付け・削除の規則、パンくず、枝への着手・打ち切り）
- `goal-blueprint`: 目標単位の設計図ビュー（プレビューとテキスト取り込みの切替、既定の展開規則、レポートとの分離、継続チェインを跨いだ引き継ぎ）

### Modified Capabilities

- `kanban-task-category`: カードのチップ表示に親のパンくずが加わるため、カテゴリチップとの併存規則を定める
- `tomorrow-plan-board`: 盤面に出るカードが「葉だけ」に絞られることを明記する

## Impact

- **DB**: `task` に3列追加するマイグレーション（`parent_task_id` / `goal_id` / `tree_order`）。既存行はすべて `NULL` = 根かつ目標なし＝現状と同じ挙動
- **サーバ**: 新規 `server/src/services/task-tree.ts`（パーサ・ツリー構築・導出・循環検査・枝操作）。`server/src/services/tasks.ts`（`listTasks` に `has_children` を付与、`deleteTask` の子の扱い）。`server/src/services/planning.ts`（容れ物を除外）。`server/src/api/planning.ts`（`/api/tasks` 系の受け口拡張）と新規 `/api/goals/:id/blueprint` 系
- **フロント**: 新規 `server/static/js/blueprint.js`（設計図ビュー）。`server/static/js/kanban.js`（容れ物を盤面から除外、パンくずチップ、分解導線）。`server/static/js/goals.js`（目標カードから設計図への導線）。`server/static/js/tomorrow-plan.js`（容れ物を除外）
- **既存 e2e**: `kanban-*.spec.ts` 群は親子を持たないタスクしか作らないため、葉＝カードの絞り込みの影響を受けない見込み。propose 側で実際に走らせて確認し、影響があればここで直す
- **デモモード**: `demo-seed.ts` に設計図のサンプル（2〜3階層・一部完了）を足し、`demo.test.ts` の期待値を更新する
- **スコープ外**: 設計図の進捗をレポートに載せること（`goal-report` は無改造）、ツリーのドラッグ&ドロップによる再親付け UI（データ側の再親付け API は用意するが、UI は別 issue）
