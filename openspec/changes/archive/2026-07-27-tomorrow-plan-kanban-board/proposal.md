## Why

issue #61 で新設した「明日の計画」ビューは、**カンバンへ登録している画面に見えない**。`rf-*` の寒色ピル・縦リストで描かれているため、同じデータ（`status=TODO` / `due=翌日`）なのにカンバンと視覚言語が二重化しており、「ここに入れたものがカンバンに入る」ことが一目で伝わらない（issue #67）。加えて本文が空だと候補チップが 0 個になり、約 1000px の左メインに入力欄 1 本と灰色 1 行しか無い空白の画面になる。

さらに機能上の穴がある。現在のビューは **新規作成しかできない**（`tomorrowTasksOf()` は `status==='TODO' && due===翌日` のみを見る）。夜の実作業は「今日やり残した TODO」「保留に積んだ物」を明日へ引き取る調整を含むが、それができないため結局カンバンタブへ行く羽目になる。

## What Changes

- 「明日の計画」ビューの**縦リストを本物のカンバン盤面（保留 / 未着手 / 進行中 / 完了）に置き換える**。振り返り本文を右に見ながら、`保留 → 未着手 → 進行中` の列間移動・新規登録・期限調整ができるようにする（＝夜の「引き取り」が成立する）。
- 盤面は**登録・調整に必要なものだけ**を持ち込む。完了時の演出（フロスト・粒子）、設定ポップオーバー、カテゴリ付けモードは持ち込まない。
- **右サイドバーをタブ切替にする**。左メインが「カンバン」のときだけ `詳細` / `アクティビティログ` タブが現れ、左が他ビューのときは閉じる。カード選択時は `詳細` タブへ自動で切り替わり、タスク完了時は `アクティビティログ` タブへ戻る。
- **左のビューが、右サイドバーのタブ構成と上部日付ストリップの有効性の両方を駆動する**という一本の規則にする。左が「カンバン」のとき日付ストリップは無効化（非表示）する。盤面には「表示対象日」が無いため、ストリップが全ビューを駆動する現行規則と衝突するのを解消する。
- **BREAKING**: 左メインのビュー切替から**横スクロール（`scroll-snap` のデッキめくり）を廃止**し、切替はビュータブのみにする。ビュー内の横スクロールは「見切れた盤面をめくる」動作へ一本化される（横スクロールが同一軸で三重に衝突するのを設計ごと解消する）。
- **BREAKING**: 「明日の計画」ビューの登録済みタスクは、余白のある縦リストではなくカンバン盤面のカードとして表示される（`tomorrow-plan-capture` の既存要件を撤回する）。
- 明日トグル（`due=翌日` で作成するモード）を埋め込み盤面に**既定 ON** で提供する。
- 本文からの候補チップ・直接入力 + Enter による登録（issue #61 の中核）は**維持する**。盤面の上にチップ帯として置く。

## Capabilities

### New Capabilities
- `tomorrow-plan-board`: 「明日の計画」ビューに埋め込む登録用カンバン盤面の範囲を規定する。持ち込む機能（4列・列間ドラッグ・新規登録・期限調整・明日トグル既定 ON・見切れとめくり）と、持ち込まない機能（完了演出・設定ポップオーバー・カテゴリ付けモード）の境界、および右サイドバーへ供給する `詳細` / `アクティビティログ` の内容を定める。

### Modified Capabilities
- `tomorrow-plan-capture`: 登録済みタスクの表示を「余白のある縦リスト」から「カンバン盤面のカード」へ変更する（縦リスト必須・詰め込み列禁止の要件を撤回）。並べ替え要件に**列間移動**を加える。候補チップ・直接入力・登録先が本物のカンバンであることは変更しない。
- `reflection-timeline-workspace`: 左メインのビュー切替から横スクロール（スナップ）を廃止しビュータブのみにする。右サイドバーを「常時表示の固定内容」から「常時表示・左ビュー連動のタブ」へ変更する。日付ストリップが「画面全体を常に駆動する」規定を「日付に属するビューのときのみ駆動する」へ変更する。参照実装 `ref/reflection/` の視覚要件を新レイアウトへ更新する。

## Impact

- **フロント**: `server/static/js/reflection.js`（デッキのスナップ廃止・サイドバーのタブ器化・ストリップの有効性ゲート）、`server/static/js/tomorrow-plan.js`（縦リスト → 盤面ホスト。チップ帯と入力欄は維持）、`server/static/js/kanban.js`（盤面・`asideEl()` / `logEl()` / `detailEl()` を埋め込み先へマウントできるよう切り出し）、`server/static/css/app.css`（ワークスペース内での `rf-*` と `kb-*` の共存）。
- **参照実装**: `ref/reflection/` を新レイアウト（盤面ビュー＋サイドバータブ）へ更新し、スクショ検証する。
- **API / サーバ**: **変更なし**。`POST /api/tasks`・`PATCH /api/tasks/:id`（`status` / `due` を含む任意フィールド）・`POST /api/tasks/reorder`・`DELETE /api/tasks/:id` は全て既存で、期限調整も列間移動も既存経路で足りる。
- **期日ロジック**: 変更なし。`kanban.js` の `computeDue()` / `tomorrowMode()` / `setTomorrowMode()` をそのまま使う（`保留 → 未着手` で `due=翌日` が付くため「引き取り」は既存ロジックで成立する）。
- **既存 e2e**: `e2e/tomorrow-plan-capture.spec.ts` が `.rf-plan-item`（撤去される縦リスト）に依存しており、本 change で更新する。
- **テスト**: 本 change は `server/static/js/` のみを触り、vitest の収集対象（`packages/*/src` / `server/src` / `extension/src`）に該当するコードを変更しない。したがって **vitest の新規レッドテストは書けない**（詳細は `tasks.md`）。
- **非対象（今回やらないこと）**:
  - **カンバンタブは廃止しない。** 埋め込み盤面は登録・調整専用で、機能パリティ（設定ポップオーバー・カテゴリ付けモード・アーカイブ復元・完了演出）を満たさない。昼の主動線は従来どおりカンバンタブに残し、埋め込み盤面が十分だと分かった時点で別 change として廃止を判断する。
  - 盤面の列構成・カード意匠・ドラッグ規則（`kanban-task-reorder` / `kanban-drag-autoscroll` 他）そのものは変更しない。
  - タイムライン・一日の配分ビューの描画規則は変更しない。

## Post-apply Amendment（issue #67 の実装後フィードバック・2026-07-27）

apply 完了後、issue #67 に以下2点の修正依頼が入り、追加で反映した。

- **直接入力欄の撤去**: 「本文からの候補チップ・直接入力 + Enter による登録は維持する」としていたが、
  盤面自身の列内コンポーザ（「＋ 新規タスク」）と機能が重複しているため、直接入力欄（`.rf-plan-input`）は
  撤去した。候補チップ（本文からのタップ登録）は維持する。
- **本日の進捗（達成件数）の表示**: カンバンタブでアクティビティログの上に出ている「本日の進捗」
  （本日達成したタスクの件数）が埋め込み盤面の「ログ」タブに無かったため、追加した。
