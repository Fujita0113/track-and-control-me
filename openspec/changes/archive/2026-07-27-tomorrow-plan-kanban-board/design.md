## Context

issue #61 で振り返りタブを左右2分割ワークスペース化し、左メインに `タイムライン / 一日の配分 / 明日の計画` の3ビューを置いた。「明日の計画」ビューは候補チップ＋入力欄＋登録済み縦リスト（`.rf-plan-*`）で構成され、登録先は本物のカンバン（`status=TODO` / `due=翌日`）である。

現状の問題は2つ（issue #67）。

1. **視覚言語の二重化** — 同じデータが `rf-*`（寒色・丸ピル・縦リスト）と `kb-*`（暖色・Notion 風カード）の2つの世界で描かれ、「ここに入れたものがカンバンに入る」と目が認識できない。
2. **機能の穴** — `tomorrow-plan.js` の `tomorrowTasksOf()` は `status==='TODO' && due===翌日` しか見ないため、今日やり残した TODO も保留に積んだタスクも視界に無く、明日へ引き取れない。

探索（issue #67）で確定した使い方は「昼はカンバンを一日中開き、タイムラインも随時開く。夜は振り返りを見ながら `保留 → 未着手 → 進行中` を調整して明日を組む」。

**制約**

- フロントは `server/static/js/` の素の ES モジュール。ビルド無し、CSP は `style-src 'self'`（インライン `style=` 禁止）。
- `kanban.js` は**モジュールレベルのシングルトン状態**を持つ（`rootEl` / `S` / ドラッグ状態群）。`show()` は `document.body` に `kb-page` クラスを付ける。
- `kb-*` の**コンポーネント CSS は `body.kb-page` にスコープされていない**（スコープされているのは `background` と `.content` の `max-width` のみ）。したがってカード・列の意匠は埋め込み先でもそのまま効く。
- サーバ API は**変更不要**。`POST /api/tasks`・`PATCH /api/tasks/:id`（任意フィールド＝`status` / `due` を含む）・`POST /api/tasks/reorder`・`DELETE /api/tasks/:id` が既存。

## Goals / Non-Goals

**Goals:**

- 「明日の計画」ビューで、振り返り本文を見ながら `保留 → 未着手 → 進行中` の調整・新規登録・期限調整ができる。
- 埋め込み盤面が「カンバンである」と説明なしに伝わる（＝`kb-*` の意匠をそのまま使う）。
- 左メインの現在ビューが、右サイドバーのタブ構成と日付ストリップの有効性を**一本の規則**で決める。
- 左メイン内の横スクロールが持つ意味を1つ（盤面のめくり）に絞る。

**Non-Goals:**

- **カンバンタブの廃止**。埋め込み盤面は登録・調整専用で、設定ポップオーバー／カテゴリ付けモード／アーカイブ復元／完了演出を持たないため機能パリティが立たない。廃止は別 change。
- 盤面の列構成・カード意匠・ドラッグ規則そのものの変更（`kanban-task-reorder` / `kanban-drag-autoscroll` 等は既存のまま）。
- サイドバーの折り畳み機能（D4 参照）。
- 候補チップの抽出アルゴリズム（`extractCandidates`）の改良。

## Decisions

### D1: `kanban.js` を「マウント可能」にする（インスタンス化はしない）

`kanban.js` に `mount(root, opts)` / `unmount()` を追加し、既存の `show()` / `hide()` はその薄いラッパにする。`opts` で埋め込み時の差分を宣言する。

| opt | カンバンタブ | 埋め込み盤面 |
|---|---|---|
| `bodyClass` | `kb-page` を付ける | **付けない**（`rf-page` を壊さない） |
| `asideHost` | 盤面の右へインライン配置 | **右サイドバーの要素**を渡す |
| `effects` | ON（フロスト・粒子・サウンド） | **OFF** |
| `settingsPopover` | ON | **OFF** |
| `categorizeMode` | 利用可 | **OFF** |
| `tomorrowDefault` | 現状維持 | **既定 ON** |

**なぜインスタンス化しないか**: `kanban.js` は 1298 行で、ドラッグ・自動スクロール・オーディオまでモジュールレベル状態に依存している。完全なインスタンス化は本 change の目的（UI の再配置）に対して過大で、リグレッション面が広い。**同時に2つマウントされない**ことを保証すれば単一状態で足りる。

**単一マウントの保証**: `mount()` は先頭で既存マウントを `unmount()` する。加えて (a) カンバンタブと振り返りタブは同時表示されない（`main.js` の画面切替）、(b) 埋め込み盤面は「明日の計画」ビューがアクティブなときだけマウントする、(c) `reflection.hide()` は埋め込み盤面を必ず `unmount()` する。

**代替案**: `kanban.js` を丸ごとコピーして軽量版を作る → 却下。`ref/kanban` 忠実移植の意匠が二重管理になり、「別物になる事故」の再発経路そのもの。

### D2: 左ビューが「サイドバーのタブ構成」と「ストリップの有効性」を駆動する

`reflection.js` に単一の純粋な写像を置き、ビュー切替時にそれだけを見て両者を更新する。

```
viewChrome(view) → { strip: 'on' | 'off', sidebarTabs: [...] }

  'timeline' → { strip: 'on',  sidebarTabs: ['journal'] }
  'alloc'    → { strip: 'on',  sidebarTabs: ['journal'] }
  'plan'     → { strip: 'off', sidebarTabs: ['journal', 'detail', 'log'] }
```

**なぜストリップを消すのか**: カンバン盤面には「表示対象日」が無い。ストリップを出したまま盤面を見せると「7/23 を選んだら盤面は何を映すのか」という答えの無い問いが生まれる。盤面を開いたらストリップが引っ込めば、説明が不要になる。

これは既存の潜在的な綻びも解消する。`tomorrow-plan.js` の `tomorrowKey()` は `ctx.activeDate` ではなく `state.today` を見ており、ストリップで過去日へ移ると候補チップ（対象日の本文由来）と登録済みリスト（常に翌日）で日付が食い違っていた。ストリップを非表示にすることで、この食い違いが**ユーザーから見えなくなるのではなく、発生しなくなる**（対象日を動かす手段がその場に無い）。

**代替案**: ストリップを出したまま盤面だけ対象日に従わせない → 却下。規則「ストリップは画面全体を駆動する」を破りつつ、破ったことが画面から読み取れない。

### D3: 左メインの `scroll-snap` デッキを廃止し、切替はビュータブのみにする

現行 `.rf-deck` は `scroll-snap-type: x mandatory` で3ビューを横に並べてめくる。盤面を入れると、同一軸に **(1) デッキのスナップ / (2) 盤面の横スクロール / (3) カードの横ドラッグ** が重なる。

デッキを廃止して「アクティブなビューだけを描く」構成にすると、左メイン内の横スクロールは盤面のめくりだけになり、衝突が設計ごと消える。ユーザーは実際の運用でも上のビュータブで切り替えており、横スクロールでのビュー切替は使われていない。

**副次効果**: `deck.addEventListener('scroll', …)` のデバウンス（130ms）で現在ビューを推定する処理と、`scrollTo` によるビュー移動が不要になり、`ensureViewRendered` の呼び出し経路が1本になる。

**代替案**: デッキを残し、盤面ビューだけスナップを解除する → 却下。同一コンテナで軸の意味が場所によって変わるのは、実装よりも操作感の説明が破綻する。

### D4: サイドバーの折り畳みは作らない

盤面 1202px（`290×4 + 14×3`）に対し、左メインの実効内側幅は次のとおり（`.content` は `padding: 20px`）。

| 状態 | 盤面の見える幅 | 完了列の見え方 |
|---|---|---|
| 現行のカンバンタブ（1440px 画面） | 1044px | 45% |
| 埋め込み（サイドバー表示） | 952px | 14% |
| （参考）サイドバー折り畳み時 | 1356px | 全部 |

列の開始位置は `0 / 304 / 608 / 912`。**952px でも 1044px でも `保留` / `未着手` / `進行中` の3列は完全に見えている**。切れるのは `完了` 列だけで、そこはドロップ後およそ 1 秒でアーカイブされて消える投函口であり、読む場所ではない。さらに `kanban-drag-autoscroll` が「特に完了列」を名指しで引き込むと規定しているため、見切れたままでもドロップできる。現行比の差は 92px。

加えて、折り畳みは**自動召喚と競合する**。カード選択で詳細タブへ、完了でログタブへ自動的に切り替わる設計なので、畳んだ状態は数秒で破られ、レイアウトが跳ねるだけになる。

**代替案**: 折り畳みトグルを付けて自動召喚をやめる → 却下。ユーザーが求めた挙動（開いたら詳細が出る／完了したら進捗が出る）と逆向き。

### D5: 期限調整は右サイドバーの詳細タブで行う（カード上に別ピッカーを作らない）

探索の途中で「詳細パネルは要らない／でも期限調整はしたい」という要求の噛み合わなさが残っていたが、詳細パネルを**右サイドバーのタブ**へ移す決定によって解消した。カードを選ぶと詳細タブが自動で開き、そこに既存のカレンダー式期限ピッカーがある。カード上に軽量ピッカーを新設する必要はない。

### D6: 明日トグルは既定 ON、期日決定は既存エンジンをそのまま使う

`computeDue(fromCol, toCol, tomorrowOn, workday)` は既に次を満たす。

- 作成（`fromCol === null`）または `HOLD` からの復帰で `tomorrowOn` なら `due = workday + 1`
- 非 HOLD → 非 HOLD の移動は据え置き
- `DONE` は触らない

したがって**「保留から未着手へ引き取ると期日が明日になる」は新規実装ゼロで成立する**。埋め込み盤面では `tomorrowDefault: true` として初回マウント時に `setTomorrowMode(true)` する（`localStorage` に日付キーで保持され翌日 OFF になる既存規則はそのまま）。

「デフォルトで期限明日のタスクを作る」と「明日トグルを既定 ON にする」はユーザーにとって等価であることが確認済みなので、既存機構に寄せる。

### D7: 既存 e2e を壊さないためのセレクタ安定契約

`e2e/tomorrow-plan-capture.spec.ts` が依存する以下は、実装後も**同じ意味で維持しなければならない**。

| セレクタ | 契約 |
|---|---|
| `.rf-plan` | 「明日の計画」ビューのルート要素 |
| `.rf-plan-chip` | 本文由来の候補チップ（登録済みは `.done` を付与） |
| `.rf-viewtab` | 左メインのビュー切替タブ |
| `.kb-card` | 盤面のカード（埋め込み盤面でも同じクラス） |

撤去されるのは `.rf-plan-list` / `.rf-plan-item` / `.rf-plan-drop-indicator`（縦リスト一式）。
**追記（issue #67 フィードバック）**: `.rf-plan-input`（直接入力欄）も撤去された。新規タスクの直接入力は
盤面自身の列内コンポーザ（「＋ 新規タスク」）が担い、専用の入力欄は重複のため置かない。

### D8: 完了は「演出だけ落として機能は残す」

`effects: false` のとき、フロスト表示・粒子アニメーション・サウンドをスキップし、**アーカイブ遷移そのものは同じ経路で実行する**。演出のディレイ（約1秒）に依存してアーカイブしている場合は、演出無しでも同じ状態遷移が起きるようタイマーを演出から分離する。

## Risks / Trade-offs

- **`kanban.js` のシングルトン状態が2箇所マウントで壊れる** → `mount()` 冒頭で既存マウントを `unmount()` し、`reflection.hide()` と ビュー離脱の双方から確実に `unmount()` を呼ぶ。ドラッグ中の `unmount()` は自動スクロール RAF とドロップインジケータの後始末を伴う。
- **`@media (max-width: 1100px) { .kb-main { flex-direction: column } }` が埋め込み時に誤発火する** → 埋め込みでは `.kb-main`（盤面＋インライン aside の flex コンテナ）を使わず、盤面スクロール要素だけを左メインに置き、aside は右サイドバーへ別マウントする。このメディアクエリの適用対象から外れる。
- **`body.kb-page` を付けないことで一部の見た目が変わる** → スコープされているのは `background` と `.content { max-width }` だけであり、いずれも埋め込み先（`rf-page`）の値を使うのが正しい。コンポーネント意匠には影響しない。
- **盤面が常に見切れる** → D4 のとおり、切れるのは完了列のみで、現行のカンバンタブでも 1440px 画面では既に見切れている（1044px）。差は 92px。
- **カード選択のたびに振り返り本文が押し出される** → タブなので戻せる。本文タブへ戻して段取りを読み直せることを `tomorrow-plan-capture` のシナリオで担保する。
- **デッキ廃止が `reflection-timeline-workspace` の既存要件と衝突する** → 当該要件を RENAMED + MODIFIED で明示的に書き換える（本 change の delta spec に含む）。
- **vitest のレッドテストを置けない** → 本 change は `server/static/js/` のみを触り、vitest の収集対象（`packages/*/src` / `server/src` / `extension/src`）に該当するコードを変更しない。凍結される契約は delta spec のシナリオと、更新済みの既存 e2e のみになる。apply は DOM 完成後に新規 e2e を書き、実装抜きで落ちることを `CI=1` 付きで証明する（`tasks.md` 参照）。

## Migration Plan

1. `kanban.js` に `mount(root, opts)` / `unmount()` を追加し、`show()` / `hide()` をそのラッパへ置き換える（カンバンタブの挙動は不変であることを既存 e2e で確認）。
2. `reflection.js` のデッキを廃止し、アクティブビューのみ描画する構成へ変更する。`viewChrome(view)` を導入し、サイドバーのタブ器とストリップの有効性を駆動する。
3. `tomorrow-plan.js` の縦リストを撤去し、チップ帯＋入力欄の下へ埋め込み盤面をマウントする。
4. `ref/reflection/` を新レイアウトへ更新し、スクショで突き合わせる。
5. デモモード（`demo-seed.ts` の固定 day_key）で振り返りタブの閲覧表示が新レイアウトへ追従していることを確認する。

**ロールバック**: 埋め込み盤面のマウントを外して縦リストへ戻せば `tomorrow-plan-capture` の旧挙動に復帰する。カンバンタブを残しているため、埋め込みが失敗しても昼の動線は無傷。

## Open Questions

- 候補チップ帯の置き場所（盤面の上に横一列 / 未着手列のコンポーザ内）。ユーザーは「デザインは気に入らなければ都度直す」方針を明言しており、apply が DOM を作る中で決めてよい。
- カンバンタブを将来廃止するかは本 change の対象外。埋め込み盤面を実際に使ってみて、カンバンタブを開かなくなったかどうかで別途判断する。
