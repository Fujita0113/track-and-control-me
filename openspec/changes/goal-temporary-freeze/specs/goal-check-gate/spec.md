## ADDED Requirements

### Requirement: 凍結中の目標のルールはゲートから外れる

システムは、対象日に**凍結中**（`goal_freeze.start_day <= dayKey <= goal_freeze.end_day`）の目標に紐づくルールを、その日の解錠評価へ**合流させてはならない**（MUST NOT）。除外は種類（時間型・非時間型・写真・質問）とスケジュール（永続・単発・範囲）を問わず一律 SHALL とする。

- ルールが複数の目標に紐づく場合、**紐づく目標がすべて凍結中のときにのみ**除外 SHALL する。1つでも凍結中でない目標に紐づいていれば、そのルールはゲートに残る SHALL。
- 単発の写真/質問ルールの繰り越しは、凍結中は止まる SHALL（ゲートに現れない）。凍結が明けた日から再び未達として現れる SHALL。
- 既に確定した過去日の評価（`unlock_evaluation.is_final`）を、凍結によって書き換えてはならない（MUST NOT）。
- その日に回答すべきルールのトースト通知も、凍結中の目標のルールを対象にしてはならない（MUST NOT）。

#### Scenario: 凍結中はゲートに現れない

- **WHEN** 凍結中の目標に紐づく総作業時間ルールがある日を評価する
- **THEN** その日の解錠評価に当該ルールは現れず、他の目標のルールだけで判定される

#### Scenario: 凍結が明けると戻る

- **WHEN** 7/28〜7/31 凍結の目標について 8/1 を評価する
- **THEN** 当該目標のルールは再び未達成条件として現れる

#### Scenario: 単発ルールの繰り越しは凍結中だけ止まる

- **WHEN** 未提出の単発写真ルールを持つ目標を 7/28〜7/31 凍結し、7/29 と 8/1 を評価する
- **THEN** 7/29 の評価には現れず、8/1 の評価には未達として再び現れる

#### Scenario: 凍結中の目標のルールはトースト通知の対象外

- **WHEN** 凍結中の目標に未回答の範囲質問ルールがある日に、その日はじめてダッシュボードを開く
- **THEN** そのルールについてのトーストは表示されない

### Requirement: 有効ルールがゼロの日は作成を促す案内を示す

システムは、その日の有効ルールが**ゼロ**になった場合（凍結の結果を含む）、解錠状態を **LOCKED のまま** SHALL とする（「実効ルールが皆無なら達成不能」という既存の判定を変えてはならない・MUST NOT）。凍結を全解除の裏口にしないためである。

このとき今日タブは、「達成不能」という結果だけでなく、**振り返りタブの目標コーナーで新しいルールまたは目標を作れば当日から解錠できる**旨の案内を表示 SHALL する。今日タブにルールの追加・変更・削除の UI を置いてはならない（MUST NOT。`editable-rule-registry` の一本化を維持する）。

#### Scenario: ルールがゼロの日はロックのまま案内が出る

- **WHEN** 唯一の目標を凍結した結果、その日の有効ルールがゼロになった状態で今日タブを開く
- **THEN** 解錠状態は LOCKED のままで、振り返りタブでルールか目標を作るよう促す案内が表示される

#### Scenario: 今日タブに作成 UI は無い

- **WHEN** その案内が表示されている今日タブを見る
- **THEN** 案内は振り返りタブへの導線のみで、ルールを作成するフォームは今日タブに存在しない

#### Scenario: 新しいルールを作れば当日に解錠できる

- **WHEN** 案内に従って振り返りタブで当日開始のルールを1つ作り、それを満たす
- **THEN** その日の解錠評価は当該ルールのみで行われ、UNLOCKED になる
