# 家計簿タブ UIモック — 設計メモ（issue #94）

`kakeibo-mock.html` を1枚開けば全画面見られる。サブタブは **ホーム / 履歴 / 分析 / 予算**。
記録カードのカテゴリ・重要度・計算対象、`予想の計算内訳・調整`、分析の明細が実際に動く。
上のタブで「今日」に切り替えると解錠ゲートの抜粋。

スクショ: `home.png` / `forecast-exclude.png` / `entry-auto-exclude.png` / `history.png` /
`history-exclude.png` / `analysis.png` / `detail.png` / `budget.png` / `today-gate.png` / `home-mobile.png`

## 5巡目で捨てたもの

#94 のコメント「複雑なロジック組みすぎた」を受け、4巡目までの
**「日数の在庫を買う」モデルを全部落とした**。捨てたのは:

予定日数・実績日数 / 名称ごとの基準4択（前回の値・全体の平均・直近N回・手動）/
記録時の「何日もちましたか」1問 / 3状態（未確定・暫定・確定）/ カバー期間の帯 /
日数の一括編集ビュー / 娯楽・急な出費の3か月平均の月枠。

## 主張

**予想は1本の平均単価で足りる。画面はそれを隠さず、ただし持ち出さない。**

計算は「今月これまでの日々の出費 ÷ 経過日数 × 月の日数」だけ。
ホームは折れ線と1行のサマリで済ませ、**計算の内訳と調整はモーダルへ畳む**。
常時見えているべきなのは結果（月末予想と超過）であって、途中式ではない。

## ホームの構成

1. **今月の支出推移と月末予想**（主役・全幅）= 折れ線 ＋ 直下に1行サマリ
2. [今週の残り予算] [今月の「無駄遣い」]
3. 記録する（予定出費チップ・内訳・レシート添付つき）

### 1行サマリ（折れ線の直下）

```
日々の出費: 1日平均 ¥1,759   特別費: ¥3,300   予定出費: ¥1,800   固定費: ¥17,380
                                              [ 予想の計算内訳・調整 › ]
```

月末予想 ¥77,010 を作っている4つの成分だけを横一列に置く。押すとモーダル。
**ここで途中式（÷経過日数・×残り日数）は見せない**。見せると読む前に降りられる。

## 折れ線

縦＝費用の累計 / 横＝時間。内訳の色分けはしない。要素は4つだけ:

| 要素 | 中身 |
|---|---|
| 切片（薄いグレー帯） | **固定費 ¥17,380**。月初から乗っている定数 |
| 実績（実線・階段） | 買った日ごとに段で上がる。**今日の点に `今日 ¥40,030` を直接書く** |
| 予想（破線） | 傾き＝1日平均 **¥1,759**（一定）、段＝予定出費（8/20 ¥1,800） |
| 上限（横の破線） | ¥62,000。予想線と交わる日に点＋「このペースだと **8/23** に上限超過」 |

傾きが一定なので線は「実績の階段 → 一定勾配の破線＋予定出費の段」の2区間だけ。
**全幅なので viewBox は 700×300**（縦長にすると線が寝て読めなくなる）。
SVG 内の文字は 7.5–8.5（描画幅 ×1.7 で本文と同じくらいになる）。

## 特別費（ペース計算からの除外）

**特別費に指定した額は実績には残り、ペース計算（1日平均）の母数からだけ抜ける。**
一時的な出費を日々の出費として引き伸ばさないための唯一の調整弁。判定は2通り:

- **急な出費（`SUDDEN`）は自動**。記録カードでカテゴリを選ぶと `計算対象` のトグルが
  on かつ disabled になり「急な出費は自動で特別費（計算除外）になります」と出る
  （`entry-auto-exclude.png`）
- **それ以外は手動トグル** `特別費にする（日々の計算から外す）`（`X`）。
  記録カード・履歴の行・調整モーダルのどこからでも切り替えられる

調整モーダル（`forecast-exclude.png`）は名称ごとに `通常の出費 / 特別費（除外）` の2値を並べ、
切り替えるたびに**保存せず**下の効果パネルを出し直す:

| | 通常の出費 | 特別費（除外） |
|---|---|---|
| 日々の出費（計算対象） | ¥19,350 | ¥15,870 |
| 1日平均 | ¥1,759 | ¥1,442 |
| 今月末の予想額 | ¥77,010 | ¥70,670 |
| 上限を超える日 | 8/23 | 8/25 |

**判定は「上限内」へひっくり返らない。** 単純な平均単価は月前半のまとめ買いを月末まで
引き伸ばすので上振れする性質があり、特別費にして縮むのは超過幅であって符号ではない。
ここを演出で覆さない。

## 内訳（任意）

レシートが無いが何を買ったか覚えているときに書く自由記述（#94「レシートはないけど
何を買ったのか覚えているとき」）。

- 記録カードに `内訳（任意）` のテキストエリア。プレースホルダは `豚こま 598 / 鶏むね 898 …`
- **見る場所はレシートと同じ**＝分析の明細。押すと `detail.png` のモーダルが開き、
  **内訳とレシートを別々の面で並べて出す**（手で書いた文字と写真を混ぜない）
- 明細行には `内訳` / `レシート` の印が付き、**どちらも無い明細は開くものが無いので押せない**
- 一覧（履歴・分析の明細）には内訳の先頭を薄字で1行だけ添える
- まとめて記録した行は内訳なし（`内訳未入力` バッジ）

## 履歴

**一覧だけ**。4巡目のカバー期間の帯も、5巡目でいったん置いた日ごとの支出の棒も落とした。
グラフはホームの折れ線で足りていて、履歴で見たいのは個々の記録だから。

行は2つの領域に割る。**左ぜんぶが1つのボタン、右が二択**なので、押し分けを間違えない。

```
[ 8/07 金  Steam サマーセール   ¥3,480  ● 娯楽  ▨  内訳 ] [ 通常の出費 | 特別費（除外） ]
└──────── 押すと明細（内訳＋レシート）─────────┘   └── ペース計算に入れるか ──┘
```

- 左のボタンの列は `買った日 / 名称 / 金額 / カテゴリ / 重要度 / 内訳・レシートの印`
- **内訳もレシートも無い行は押せない**（分析の明細と同じ規則）。ただし
  *記録が無効なわけではない*ので、`[disabled]` の既定の減光は打ち消して色は落とさない。
  押せないことは hover が付かないことで示す
- 右の二択は全行に出す（`history-exclude.png`）。特別費を選ぶと行が斜線地になる
- **急な出費の行は二択を無効**にし、`特別費（自動）` を選択済みで薄く出す。
  記録カードの `計算対象` と同じ規則（自動で外れ、手では戻せない）

4巡目の「Steam の行にだけ `特別費にする` ボタン」はやめた。1行だけ操作が生えていると、
なぜその行だけなのかが読めず、他の行は変えられないと誤解される。

## 分析

`カテゴリ → 名称 → 明細` の3段。カテゴリと名称は既定で全部見えていて、名称を押すと明細が開く。
棒は全段で同じ ¥ スケール、段の深さは名前の字下げだけ、`%` は一段上に対する割合。円グラフは使わない。

## 語彙（実装はこの語で統一する）

| 概念 | 使う語 | 使わない語 |
|---|---|---|
| ペース計算の母数 | 日々の出費（計算対象） | 按分するもの |
| 1日あたり | 1日平均 | 日単価 |
| 除外した出費 | 特別費 | 予想から外したもの |
| 月末の見込み | 月末予想 / 今月末の予想額 | 着地予想 |
| 重要度の最下位 | 無駄遣い | いらない / 不要な支出 |
| まとめ登録の内訳 | 内訳未入力 | 内訳なし |
| 週の残り | 今週の残り予算 | 今週使える残り |

## トークン

| | 値 |
|---|---|
| 面・線・角丸 | 既存 app.css をそのまま継承 |
| カテゴリ4色 | 食品 `#1a8a63` / 日用品 `#4a68d8` / 娯楽 `#c94f92` / 急な出費 `#d1762f` |
| 重要度 | 色を増やさず 必須=塗り / 準必須=薄塗り / 無駄遣い=45°斜線 / 内訳未入力=点線 |
| 特別費 | 45°の斜線地（`kb-hist-row.off` / `kb-rec.off`）。必ずラベルと併記 |
| 状態色 | 超過 `#b3261e`、上限超過 `--warn` |
| 折れ線 | 実績=`--text` 実線 / 予想=`--muted-2` 破線 / 上限=`--warn` 破線 / 固定費帯=`--line-2` |
| 二択（`kb-toggle`） | 選択中=`--text` 塗り / 自動で確定している行は `.auto` で薄く＋`disabled` |
| 書体 | 本文=既存 `--font` / 金額=同ファミリ tabular-nums 700 / 目盛り・%=`Cascadia Mono, Consolas` |

カテゴリ4色は dataviz の `validate_palette.js` で検証済み（light・白面・全項目 PASS）。

## 数字の筋書き（2026-08-11 時点・31日の月・経過11日・残り20日）

```
固定費 17,380 ＋ 変動費実績 22,650 = 実績 40,030
  日々の出費（計算対象）19,350 ／ 特別費 3,300（歯医者・急な出費・自動）
1日平均 = floor(19,350 ÷ 11) = 1,759
残り    = 1,759 × 20 = 35,180
月末    = 40,030 ＋ 35,180 ＋ 予定出費 1,800 = 77,010   上限 62,000 → ▲15,010・8/23 に超過
```

- Steam ¥3,480 も特別費にすると: 計算対象 15,870 → 1日平均 **1,442** → 月末 **70,670**（▲8,670・8/25）
- 「無駄遣い」を上限ぶん ¥920 抑えると: 月末 **74,410**（▲12,410）
- 週の目標 `floor10(44,620 ÷ 31 × 7)` = 10,070 / 今週の残り予算 8,170・残り6日・1日 1,360
- 無駄遣い 4,920（変動費の 22%・上限 4,000 を 920 超過）

**先に切り捨ててから残り日数を掛ける**（`1,759 × 20`。`19,350 ÷ 11 × 20 = 35,181` ではない）。
画面の1日平均と月末予想が算数として合っていないと、数字を信じるのをやめられる。

## 実装時に忘れないこと

- ショートカット（`1`–`4`・`Q W E`・`X`・`Ctrl+Enter`・`Ctrl+M`・`0`）は `attachTooltip` でホバーヒント必須
- 折れ線は素の SVG で足りる（線3本・段・点）。Chart.js は要らない
- 予想はサーバが `series` まで作って返し、クライアントは写すだけ（式を2箇所に書かない）
- 特別費の額は**実績には残す**。ペース計算の母数からだけ抜く
- 内訳もレシートも無い行・明細は押せないこと。ただし**色は落とさない**
  （`[disabled]` の既定の減光は打ち消す。記録が無効という意味になってしまう）
- 履歴の行は「左＝明細を開くボタン / 右＝二択」の2領域。**二択を行のボタンの内側に入れない**
  （ボタンの入れ子は不正で、押し分けも壊れる）
- 特別費を切り替えたら、履歴でもホームの1行サマリと折れ線を引き直す
- 調整モーダルの行を切り替えたら、**必ず効果パネルの4行を出し直す**
  （モックは Steam の行だけ実データで動く。実装では全行が効くこと）
