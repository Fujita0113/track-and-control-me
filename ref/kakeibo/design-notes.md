# 家計簿タブ UIモック — 設計メモ（issue #94）

`kakeibo-mock.html` を1枚開けば全画面見られる。サブタブは **ホーム / 履歴 / 分析 / 予算**。
折れ線右の「予想のもと」の行、`記録する`、履歴の `何日もった？` / `日数をまとめて直す`、
分析の明細（レシート付き）が実際に動く。上のタブで「今日」に切り替えると解錠ゲートの抜粋。

スクショ: `home.png` / `source-basis.png` / `confirm-days.png` / `history.png` / `edit-days.png` /
`analysis.png` / `receipt.png` / `budget.png` / `today-gate.png` / `home-mobile.png`

## 主張

家計簿を「金額の台帳」ではなく **「日数の在庫を買う行為の記録」** として描く。
#94 の予測が日単価 × 残り日数で動くのだから、画面の主役も日数であるべき。

## ホームの構成（4巡目）

1. **今月の推移と着地予想**（主役・全幅） = 折れ線 ＋ 右に「予想のもと」
2. [今週あと使える] [今月の「いらない」]
3. 記録する（予約チップ・レシート添付つき）

**食料の持ち日カードは削除した**（履歴の「日数のカバー状況」と同じ帯で重複していた）。
未確定の合図は「予想のもと」の `未確定1` バッジと履歴の黄色い行が担う。

## 折れ線

縦＝費用の累計 / 横＝時間。内訳の色分けはしない。要素は4つだけ:

| 要素 | 中身 |
|---|---|
| 切片（薄いグレー帯） | **固定費 ¥17,380**。月初から乗っている定数 |
| 実績（実線・階段） | 買った日ごとに段で上がる。**今日の点に `今日 ¥40,030` を直接書く** |
| 予想（破線） | 傾き＝日数ものの日単価の合計、**段＝予約**（8/20 ¥1,800）、日数を持たない散発は平均を均す |
| 上限（横の破線） | ¥62,000。予想線と交わる日に点＋「このままだと **8/28** に上限を超える」 |

日数が0のものは傾きを作らない（段か切片か平均の均し込みになる）。だから一次関数ではなく折れ線。

## 予想のもと（折れ線の右・押すと編集）

**何日周期でいくらか**を1行ずつ並べる。行＝`名称 / 周期・金額 / 日単価 / 基準`。合計が「残り20日の予想」。

| 名称 | 周期・金額 | 日単価 | 基準 |
|---|---|---|---|
| 業務スーパー `未確定1` | 5日ごと ¥4,200 | ¥840/日 | 前回の値 |
| コンビニ・外食 | その日限り | ¥230/日 | 全体の平均 |
| ドラッグストア | 22日ごと ¥1,565 | ¥71/日 | 全体の平均 |
| 床屋 `予約` | 30日ごと · 次は 8/20 | ¥1,800 | 予約の値 |
| 娯楽 | 月 ¥4,500 | 残り ¥1,020 | 3か月の平均 |

行を押すとモーダル（`source-basis.png`）。**基準を3つから選ぶ**:

- **前回の値** — 直近1回。買うものが変わった店に使う（¥840/日 → 着地 ¥65,670・上限超え）
- **全体の平均** — 確定した全回をまとめた率（¥632/日 → 着地 ¥61,510・上限内）
- **直近 N 回の平均** — N はステッパー。部分平均（N=2 で ¥656/日 → 着地 ¥61,990・上限内）

選ぶと **周期・金額・日単価・着地予想がその場で出し直される**（判定がひっくり返るのが見える）。
下に確定回の履歴（未確定は「除外」と明示）、さらに下に **手で決める**（周期と金額を直接入力）。
同じモーダルは `日数をまとめて直す` の名称サマリからも開く。

## ズレにどこで気づくか

**買い出しを記録した瞬間に1問だけ聞く**（`confirm-days.png`）。

| 選択肢 | 意味 | 実績 |
|---|---|---|
| まだ残っている — あと **N** 日分 | 一食だけ残っている状態で買いに来た | 経過 ＋ N |
| 今日ぶんで切れた（既定） | ちょうど切れた | 経過 |
| もっと前に切れていた — **N** 日前 | 切れてからコンビニでしのいだ | 経過 − N |

「まだ残っている」を選ぶと今回の買い物は前回が切れた翌日から効き始める。
逃げ道は「あとで」＝未確定のまま残り、履歴の黄色い行と `未確定1` バッジで追える。
未確定は日単価の母数に入れない。

## 日数の一括編集（履歴 → 日数をまとめて直す）

`edit-days.png`。日数を持つ買い物を月をまたいで縦に並べ、予定日数と実績日数の両方をステッパーで直す。
各行に日単価（進行中は薄字＝暫定）、状態は `未確定 / 暫定 / 確定`。
一番下に名称ごとのサマリ（前回・全体の平均）＋現在の基準＋「予想のもとを変える」。

## レシート（任意）

- 記録カードに `レシート（任意）` の行。サムネイル＋ファイル名＋`選び直す`／`外す`
- **分析の明細を押すとレシートが開く**（`receipt.png`）。明細行には `レシート` の印が付き、
  付いていない明細は開くものが無いので押せない
- モーダルは日付・カテゴリ・重要度・日数バッジ＋画像。差し替えもここから

## 毎月の予約

予算タブの「毎月の予約」（床屋 30日ごと ¥1,800・次は 8/20 / コンタクト 90日ごと ¥4,200）。
**予想にだけ入り、実績にはならない。** 折れ線では予定日の段、記録カードではチップとして出て、
押すと目安金額が入った状態になり、実際の金額に直して記録すると実績に置き換わる。

## 分析

`カテゴリ → 名称 → 明細` の3段。カテゴリと名称は既定で全部見えていて、名称を押すと明細が開く。
棒は全段で同じ ¥ スケール、段の深さは名前の字下げだけ、`%` は一段上に対する割合。円グラフは使わない。

## トークン

| | 値 |
|---|---|
| 面・線・角丸 | 既存 app.css をそのまま継承 |
| カテゴリ4色 | 食品 `#1a8a63` / 日用品 `#4a68d8` / 娯楽 `#c94f92` / 急な出費 `#d1762f` |
| 重要度 | 色を増やさず 必須=塗り / 準必須=薄塗り / いらない=45°斜線 / 内訳なし=点線 |
| 状態色 | 超過 `#b3261e`、未確定・上限超え `--warn`（必ずラベルと併記） |
| 折れ線 | 実績=`--text` 実線 / 予想=`--muted-2` 破線 / 上限=`--warn` 破線 / 固定費帯=`--line-2` |
| 書体 | 本文=既存 `--font` / 金額=同ファミリ tabular-nums 700 / 目盛り・日数・%=`Cascadia Mono, Consolas` |

カテゴリ4色は dataviz の `validate_palette.js` で検証済み（light・白面・全項目 PASS）。

## 数字の筋書き（2026-08-11 時点）

固定費 17,380 ＋ 変動費実績 22,650 = 実績 **40,030**。
予想 = 業務スーパー 840×20 ＋ コンビニ・外食 230×20 ＋ ドラッグストア 71×20 ＋ 予約 1,800 ＋ 娯楽 1,020 = **25,640**。
着地 **65,670** / 上限 62,000 → ▲3,670、上限を超えるのは 8/28。
基準を全体の平均に変えると 61,510（上限内）。いらない 4,920（上限 4,000 を 920 超過）。

## 実装時に忘れないこと

- ショートカット（`1`–`4`・`Q W E`・`Ctrl+Enter`・`Ctrl+M`・`0`）は `attachTooltip` でホバーヒント必須
- 折れ線は素の SVG で足りる（線3本・段・点）。Chart.js は要らない
- 帯は「1日=1列」のグリッド。列数は `--cols` をルーラーとレーンに配る。
  同じ列に複数の要素を置くときは `grid-row` を明示しないと下段へ落ちる（実測でハマった）
- 未確定レコードは日単価の母数から除外し、除外していることを画面に出す
- レシート画像はローカル保存。分析の明細から参照できる ID を持たせる
