# 自動実装パイプライン セットアップ手順

`size/XS` の issue から自動で Pull Request が作られる仕組みを入れました。
**動かすにはあと4ステップ必要です。** 所要時間は15分ほど。

> このファイルはセットアップが終わったら削除して構いません。

---

| | 状態 |
|---|---|

| opencode 用スキル（`.opencode/`） | ✅ 生成済み |

## ステップ 1：OpenCode Go に登録して API キーを取る

1. ブラウザで **https://opencode.ai/auth** を開く
2. サインインする
3. **Go プラン**を購読する（初月 $5、その後 $10/月）
4. API キーが表示されるので**コピー**する

> ### ⚠️ 必ずやってください
> 設定画面に「残高が減ったら自動チャージ」(auto-reload) の項目があれば、**オフにしてください。**
> オンのままだと、使いすぎたときに気づかないまま追加課金されます。
> オフなら上限に達した時点で止まるので、想定外の請求が来ません。

Go プランの使用量上限は **$12/5時間・$30/週・$60/月**です。

---

## ステップ 2：コピーしたキーを GitHub に登録する

1. https://github.com/Fujita0113/track-and-control-me を開く
2. 上のタブから **Settings**（歯車アイコン）をクリック
3. 左メニューの **Secrets and variables** をクリック → その下の **Actions** をクリック
4. 緑色の **New repository secret** ボタンをクリック
5. 2つの欄に入力する
   - **Name** … `OPENCODE_API_KEY` （この綴りのまま、すべて大文字）
   - **Secret** … ステップ1でコピーしたキーを貼り付け
6. **Add secret** をクリック

---

## ステップ 3：GitHub に「PR を作る権限」を与える

**これを忘れると動きません。** 初期設定では GitHub Actions は読み取り専用なので、PR を作れません。

1. 同じ **Settings** の左メニューから **Actions** をクリック → その下の **General** をクリック
2. ページを一番下までスクロールし、**Workflow permissions** という見出しを探す
3. **「Read and write permissions」** のラジオボタンを選ぶ
4. すぐ下の **「Allow GitHub Actions to create and approve pull requests」** にチェックを入れる
5. **Save** をクリック

---

## ステップ 4：GitHub にアップロードする（Claude に頼む）

作ったファイルは、まだ**あなたのPCの中だけ**にあります。
GitHub Actions は GitHub 上にあるファイルしか実行しないので、送らないと動きません。

Claude に **「push して」** と伝えてください。代わりに実行します。

（勝手に公開リポジトリへ送るのは避けたため、この一手間だけ残してあります）

# 使い方

## タスクサイズのラベル

issue には大きさのラベルを付けます。**自動実装が走るのは `size/XS` だけ**です。

| ラベル | 意味 | 自動実装 |
|---|---|---|
| 🟢 `size/XS` | 極小。バグ修正、細かいUX改善 | **走る** |
| 🟡 `size/S` | 小。1画面・1機能で収まる変更 | 走らない |
| 🟠 `size/M` | 中。複数箇所にまたがる。設計判断あり | 走らない |
| 🔴 `size/L` | 大。画面設計や仕様の作り込みが必要 | 走らない |

`size/XS` の目安は「**画面設計の判断が要らない**」ことです。
どこを直せばいいかが決まっていて、迷いどころが無いもの。

## 自動実装の流れ

1. GitHub で issue を作り、直したいことを書く
2. 右側の **Labels** から **`size/XS`** を選ぶ
3. 10〜20分待つ
4. Draft PR ができるので、中身を確認する
5. 問題なければマージする（後片付けは自動）

やり直したいときは、その issue に **`/xs`** とコメントするだけです。

## 裏で何が起きているか

```
size/XS ラベルを付ける
   ↓
① 原因を特定して提案を作る        （deepseek-v4-pro）
   ↓
② 提案どおりに実装する            （kimi-k2.7-code）
   ↓
③ テストを全部実行               （型検査・279件のユニット・E2E）
   ↓  失敗したら1回だけ修正を試みる
④ 仕様書（openspec/specs/）を更新  （deepseek-v4-pro）
   ↓
⑤ 画面のスクリーンショットを撮る
   ↓
⑥ Draft PR を作る
   ↓
   あなたがレビューしてマージ
   ↓
⑦ OpenSpec の変更を archive へ移動（AI不使用・追加費用なし）
```

## 画面の見た目を確認する方法

このアプリはローカル完結（拡張機能＋ローカルサーバ）なので、Vercel のような
プレビューURLは作れません。代わりに**デモモードの画面写真**を自動で撮っています。

1. PR のページから、リンクされた **Actions の実行ページ**を開く
2. ページ下部の **ui-screenshots** をクリックしてダウンロード
3. 全6タブ（今日／タイムライン／カンバン／振り返り／目標／設定）の画像が入っています

# レビューで見てほしい点

自動化しても、**マージの判断だけは人間が持ちます**（自動マージは無効のまま）。
特に次の2つは目を通してください。

### 1. `openspec/specs/` の差分

ここはプロジェクトの正典で、37個ある日本語の仕様書です。以降のすべての変更の土台になります。
AI が自動でマージするので、**日本語が劣化していないか**を見てください。
ここさえ荒れなければ、あとは安心して回せます。

### 2. `e2e/` の差分

テストを都合よく書き換えて「緑」にする、という失敗が起きうる箇所です。

対策として、`tasks.md` に「このテストをこう変える」と**事前に書かれている場合だけ**
テストを変更してよい、というルールをプロンプトに入れてあります。

なので `e2e/` に差分がある PR では、`tasks.md` に書かれた理由と実際の変更が
一致しているかを確認してください。

# 未処理の宿題（急ぎではない）

## `e2e/plan-check-loop.spec.ts` が一時停止中

このテストは**元から失敗していました**（今回の作業とは無関係）。

issue #59（`goal-rule-lifecycle`）で「採用モデル」と Plan-Check を撤去したとき、
このテストだけが取り残されていました。`POST /api/goals` に `practices: ['manual:...']`
を渡していますが、この形式はもう受け付けられません
（ルール追加は `POST /api/goals/:id/rules` に変わっています）。

**撤去済みの機能をテストしているだけなので、アプリが壊れているわけではありません。**

放置すると自動実装のたびに「テスト失敗」と判定され、無関係な修正に課金枠を浪費するため、
`test.fixme()` で一時停止し、理由をコメントで残してあります。削除はしていません。

対応は2択です。手が空いたときに決めてください。

- **a) 書き直す** … 現在のユーザーフロー（ルール identity 化後）に合わせる
- **b) 削除する** … 役目を終えたものとして消す

## OpenSpec CLI のバージョン

- ローカル：**1.4.1**（`.opencode/` のスキルもこの版で生成）
- 最新：**1.6.0**

# コストの目安

1件あたりおおよそ **$0.3〜1.0** と見込んでいます（モデル単価からの概算で、実測ではありません）。
Go の上限が月 $60 なので、月に数十件は回せる計算です。

最初の数件で実際の消費量が見えるので、そこで判断してください。

## 使っているモデル

`.github/workflows/xs-auto.yml` の先頭にある2行を書き換えれば差し替えできます。

| 役割 | モデル | 単価（100万トークンあたり） |
|---|---|---|
| 調査・提案・仕様更新 | `opencode-go/deepseek-v4-pro` | 入力 $0.435 / 出力 $0.87 |
| 実装 | `opencode-go/kimi-k2.7-code` | 入力 $0.95 / 出力 $4.00 |

Go には `kimi-k3`（オープンウェイト最高性能）もありますが、$3/$15 と7倍以上高く、
Go の上限がドル建てなので割に合わないと判断しました。
品質に不満が出たら `MODEL_SMART` を `opencode-go/kimi-k3` か `opencode-go/glm-5.2` に上げてください。
